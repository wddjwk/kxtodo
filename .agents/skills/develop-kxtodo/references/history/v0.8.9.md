# v0.8.9 剪切板同步 + 应用内 iframe 回退 + 一批界面收口

> 这一版的主体是**工具箱里的剪切板同步**：文字 / HTML / 图片 / 文件在「直接 IP → 局域网 → P2P」三种线路里按优先级择一发送，不保存历史。其余是六个界面/正确性需求：应用内打开改回同窗口 iframe、安卓编辑器原生选择菜单、定时任务编辑流程、窄屏取色盘、侧栏所有区域的右键菜单、记账报表统计。

## 一、剪切板同步（需求 1）

### 数据与身份

- 核心在 `src-tauri/crates/core/src/clipboard_sync.rs`，设置结构 `ClipboardSettings` 在 `model.rs`。
- **设备身份 = 持久化的 iroh 密钥**：`runtime/clipboard-identity.json` 存 hex 私钥，`EndpointId.to_z32()` 同时用于 LAN 广播、P2P 目录与直接 IP 握手。三路发现到同一台设备时按同一个 id 合并，**只发一次**（发送端按 `deviceId` 去重；接收端再按消息 id 去重 5 分钟兜底）。
- **不保存剪切板内容**：文字 / HTML / 图片只在内存与网络里过一手；只有收到的**文件**必须落盘（系统剪切板要引用本地文件），默认 `download_dir()/kxtodo-clipboard`，可在工具页改目录。`runtime/clipboard-inbox/` 只存安卓端待写回剪贴板的图片，24 小时后清理。
- 同步口令（≥8 位，工具页可一键生成 12 位）是三种线路**共用的唯一钥匙**。所有 LAN 载荷用 `ChaCha20-Poly1305`（口令派生组密钥 + 每次连接的双 nonce 派生会话密钥）；P2P 走 QUIC 自带加密后再叠同一套帧。**不提供明文回退**。
- **ALPN 独立**：`kxtodo-clipboard/1`，房间前缀 `kxtodo-clipboard/v1/room/`；绝不能复用同步的 `kxtodo-p2p/1` 或传输的 `kxtodo-transfer/1`——同一端点上的 ALPN 是唯一路由依据。

### 传输

- **网线发现**：`UDP 52178` 每 2 秒广播 + 组播，包内只放设备 id / 名字 / TCP 端口 / 口令 HMAC 标签。TCP 监听默认 `52179`，被占用时退临时端口；设置保存触发的重启会先重试默认端口 6 次（120ms），避免每次保存都把端口换成随机值。
- **直接 IP**：工具页一行一个 `ip` 或 `ip:port`，优先尝试；定时 ping 学回设备 id 后与 LAN/P2P 目标合并。
- **P2P**：复用传输/同步的 relay 与 pkarr 目录（relay 三态沿用 `transfer.relay` → `sync.p2pRelay`），发布房间条目 + 名字记录；每 2 秒轮询房间。relay/目录变化也进服务签名，会重建端点。
- 发送失败按 direct → LAN → P2P 逐条降级；同一台设备只选一条成功线路。

### 类型与上限

- 接收端按 `textMb`（默认 1）/ `htmlMb`（2）/ `imageMb`（10）/ `filesMb`（100）过滤；关闭的类型、超上限的类型直接丢弃，整条都不可用就只回 ok 不写本机剪贴板。
- 发送端也先按本机上限裁剪（避免把 500MB 文件读进内存），文件按 `tokio::fs` 分块流式读写；单帧 256KB，硬上限防恶意巨帧。
- 桌面用 arboard（Windows 额外用 clipboard-win 读 CF_HDROP / CF_HTML）；Windows 轮询用 `GetClipboardSequenceNumber` 跳过未变化，避免每 800ms 重编码大图。Linux 无序列号，文本/HTML 已有时不重复读图片。
- 安卓受系统限制：**只有前台能读**。`MainActivity` 在 `onResume` 注册 `OnPrimaryClipChangedListener`、`onPause` 注销；变化只发一个 `kxtodo-native-clipboard` 事件，前端经 Kotlin 桥读内容后调用 `clipboard_local_changed`。首次读取只建基线不发送（可能是后台时复制的旧内容）。远端写回也经桥；后台进程可能延迟到前台才写。

### 设置与生命周期

- `settings.clipboard.*` 全部**本机偏好，不进同步共享子集**；工具页一次写整份（`gui.clipboard-configure`），避免逐字段触发多次服务重启。
- 服务生命周期挂 `HostCore::reconcile_clipboard_sync`：启动、`emit_domain_event(Settings)` 都走同一条路；总开关关闭后 `apply_remote` 还会再判一次 `cancel`，已经握手的连接也不能再写。
- `kxtodo://clipboard` 事件：`status`（在线设备、端口、最近事件）与 `remote`（安卓写回内容）。状态命令 `clipboard_status`。

## 二、应用内打开回退为同窗口 iframe（需求 2）

- `backend.ts::openLink` 的 `app` 档在所有平台都只派发 `kxtodo-preview-link`；`Workspace` 的 `.link-preview-overlay` 恢复为 `{#if linkPreviewUrl}`，桌面与安卓都不再新开原生窗口 / Custom Tabs。
- iframe 的 `sandbox` 去掉 `allow-popups`（网页不能弹新窗口），保留 `allow-scripts allow-same-origin allow-forms`；`referrerpolicy="no-referrer"`。
- 出口保留：右上角「在系统浏览器打开」+ 关闭 X；Esc（焦点在主文档时）与安卓返回键都关预览。返回键走 Workspace 的 `createBackGuard`——它按 active 翻转注册，所以在日记/记账页里打开预览时注册得比页面 guard 晚，能先吃掉返回。
- **整页覆盖时预览仍可用**：`coveredByFullPage` 在 `linkPreviewUrl` 非空时解除 `inert`，`.link-preview-overlay` 显式 `visibility: visible`——否则日记/记账/工具箱的整页覆盖会把工作区藏起来，预览虽在 DOM 里却看不见/点不动。
- 删除桌面 `open_link_preview` 命令与安卓 `openCustomTab` / Custom Tabs 依赖；`extract_link_meta` 的隐藏元数据窗口保留。
- **安卓桥 token**：`addJavascriptInterface` 会注入到所有 iframe。`ApkBridge` 的每个方法都要求 MainActivity 只往主 frame 写的随机 token；外部网页跨源读不到父窗口变量，就无法读剪贴板/分享文件/装 APK。

## 三、安卓编辑器原生选择菜单（需求 3）

- 两个编辑器 overlay 的 `on:contextmenu|preventDefault` 改成「桌面 preventDefault、移动端放行」；放行后系统才会弹复制/剪切/全选/粘贴。
- 移动端**不启用 CodeMirror 的 `drawSelection()`**：自绘选区会隐藏原生选区，安卓长按只剩一条高亮、不弹操作菜单。桌面继续自绘。
- `.cm-content` 显式 `user-select:text`、`-webkit-touch-callout:default`。

## 四、定时任务（需求 4）

- 删除按钮：`.settings-button.danger` 的 `inline-flex` 会盖掉 workspace 里的 grid，用 0,3,0 的 `.scheduler-panel .scheduler-delete.settings-button` 按回 `display:grid; place-items:center`。
- 步骤标题再点当前步骤 = 折叠；`postpone` 的判据用「`steps[id] ?? 1`」——渲染默认就是 1，不这样第一次点会被当成「打开第 1 步」（本版实测到的 bug）。
- 「执行什么」改成与「何时执行」同一套方块：脚本 / 可执行文件 / 发送通知，各有图标与说明；移动端仍只有通知。
- 试运行 / 取消 / 保存统一 `min-width:96px`，移动端三等分。
- **下次触发**：新增 `scheduleEditor.ts::nextRunInstant`，逐条照 core `plan.rs::compute_next_run`：interval 用 `lastRunAt → updatedAt → createdAt` 锚点，condition 用 `lastProbeAt` 与 `max(every, cooldown)`，calendar 用 Cron + 时区，once 受 runCount 限制，最后统一判 `until`。禁用时直接显示「未启用」，不再虚构一个 now+step 的时间。`scheduleAdapter.entryToUi` 补映射 `lastProbeAt`。

## 五、窄屏取色盘（需求 5）

- 根因是 v0.8.7 的反缩放层仍在文档流里：iro 的布局宽 = 宿主宽 × uiScale，uiScale > 1 时把 grid 轨道撑大，HEX/RGB/按钮一起溢出。
- 修法：`.kx-color-panel` 单列 `minmax(0,1fr)` + `overflow:hidden`；`.kx-color-canvas` 相对定位、`min-width:0`；`.kx-color-canvas-scale` 改 `position:absolute`，布局尺寸不再参与父级 grid。`applyPickerSize` 的宽度/高度补偿保持不变。
- 回归：v089 在 392×850、uiScale=1.5 下断言面板与每一个子元素都在面板/视口内且无横向溢出。

## 六、侧栏右键菜单（需求 6，追加需求扩展）

- **所有区域**都有「展开全部 / 收起全部」，作为分割线后的独立区：固定区每一行、树行、树空白区、资料卡/搜索框/分隔线。`gui.set-all-collapsed` 一次写所有分类的 collapsed（UI-only 命令，不进审计台账）。
- 固定区所有行都能右键（不再只有钉住的工具）：选择布局（单列 / 双列 / 只图标，勾选）、添加固定、取消固定。
- **添加固定**是草稿：列出全部基础功能（我的一天/计划内/收藏/日记/记账/定时任务/工具箱）的勾选，工具箱单独一个「工具箱内的工具」二级菜单列出所有子工具；底部取消/确认，确认才写 `appearance.navItems`；至少保留一个固定项。
- 移动端三级菜单：`subDeep` 时只显示最深的工具列表；「返回」按**深度快照**逐级退（先关最深，再关上一层），并让 MenuItem 的全局捕获点击监听避开 `.submenu-back`——否则 capture 先于 goBack 把每一层都关掉。没有深度快照时三级一次退光。
- 三列布局与工具子工具分开：工具箱本身是 `toolbox` 行，子工具是 `tool:<id>` 行，互不影响。

## 七、记账报表统计（需求 7）

- 分类占比下新增「报表统计」：无边框表格（时间 / 收入 / 支出 / 结余），日/月/年段控复用 `.ledger-segmented`。
- 粒度默认只看顶部周期：周/月→日、年→月、总→年；自定义看跨度（跨年→年、跨月→月、月内→日）。默认值只依赖周期选择，不依赖 entries——否则每次记账写入都会把用户手选的粒度顶回去。
- 结余 = 该期间净额（收入 − 支出），与汇总卡、趋势线、CLI `netCents` 同口径；转账不计入任何一列。
- 报表只列有流水的期间，空档不铺 0 行（「总」用日粒度时不会出现几千行空表）。
