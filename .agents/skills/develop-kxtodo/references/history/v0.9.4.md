## 二、图标选择器分类间隔（需求 2）

- 根因：`.icon-grid` 固定 `height:238px` + 默认 `align-content:stretch`——选具体分类只剩两三行时
  隐式行轨被均分拉伸填满 238px，按钮钉死 42px，多出的高度全变成行间空隙。「全部」行多溢出滚动故不显。
- 修：`align-content:start` + `grid-auto-rows:42px`（sidebar.css）。移动端同一条规则覆盖，同病同修。
- 回归 v094 第 2 节量「第二行 top − 第一行 bottom」≤12px（只数图标个数测不出拉伸）。

## 三、习惯多次打卡（需求 3）

- **数据形状决策**：`checkins` 保持 `Vec<String>`/`string[]` 但**允许多重日期**（出现次数=当天已打次数），
  新增 `targetCount`（1-99，serde default 1）。为什么不改 `{date:count}` 对象：`repo.rs::load_data`
  反序列化失败是 `DATA_CORRUPTED` 硬错误，会带走**整个 data.json**（nodes/tasks 一起）——
  多重数组让旧数据天然可读（每天一条=打了一次），零迁移代码满足铁律 3.3 又不炸端。
- core：`Habit::checkin_count/is_complete`；`habit check` 不带 count +1（打满幂等）、带 count 绝对设值
  （0..=target，超拒 `HABIT_COUNT_INVALID`）、uncheck 清空当天；add/modify `--target-count`。
  统计口径：连续/完成率按**打满**日算；累计/本月按**次数**算（界面单位改「次」）。
- 前端：`habits.ts` `isChecked`→`isComplete`+`checkinCount`+`checkinProgress`+`habitTarget`，
  `toggledCheckins`→`tappedCheckins`（没打满+1/打满清空）；`normalizeHabit` **不再去重** checkins。
  actions `setHabitCheckin`→`tapHabitCheckin`。
- 观感：每日圆阵部分完成 = 淡底 + **外圈 conic-gradient 进度环**（radial mask 画 3px 环，
  `--habit-fill` 角度；图标始终留淡底上不压字）+ 圆内 `count/target` 徽标；`{#key checkinCount}`
  重挂圆圈让 pop 动效每次 +1 都重放。月历热力图三态（实心=打满/主色描边淡底=部分/灰描边=计划内），
  圆收紧凑 `width:min(100%,30px)` 居中（原来 aspect-ratio 撑满整列 ~66px 太拥挤）。
- 默认图标 bug：`CalendarCheck` 不在 ledger_icons 白名单（渲染回退 Ellipsis、保存拒 HABIT_ICON_INVALID）；
  默认与所有 fallback 改 **CalendarDays**（已在白名单，零目录改动）。
- 编辑器加「每日次数」行（NumberField 1-99 + 提示文案）。

## 六、AppImage 真正跑得起来（需求 6）

- 根因（v0.9.3 只修了 glibc 基底，没修 GLib 符号）：linuxdeploy-plugin-gtk 把构建机旧 GLib(2.72) 打进包，
  AppRun 的 LD_LIBRARY_PATH 让它优先加载；24.04 系统托盘库 libayatana-ido3 按 GLib 2.80 编译找
  `g_once_init_leave_pointer`/`g_task_set_static_name` 找不到 → libappindicator dlopen 失败 → **panic exit 101**。
  gvfs/canberra 的 undefined symbol 噪音同根因。
- 修三件：① release.sh 解包→删 GLib 家族五库+gio/modules→sed 删 AppRun 的 GIO_MODULE_DIR 导出→
  appimagetool 重打包（缓存+ghfast 镜像回落）；GLib 各发行版必装且 ABI 向后兼容，22.04 构建的 webkit
  链接的符号在 22.04+ 系统 GLib 都有。② `lib.rs` setup_tray 调用包 `catch_unwind`
  （libappindicator-sys dlopen 失败是 panic 不是 Err，原有 Result 降级接不住；release 禁 panic=abort 故 unwind 可用）。
  ③ `scripts/verify-appimage.sh`：ubuntu:22.04/24.04 容器真启动（xvfb+dbus，--appimage-extract-and-run 免 FUSE，
  seccomp=unconfined+shm-size 给 WebKit 沙箱活路），断言活过 30s（timeout 124）且日志无
  panicked/Failed to load ayatana/undefined symbol；release.sh 有 docker 就跑（CI runner 自带），失败拒发布。
- pin ubuntu-22.04 依旧不能撤（webkit/javascriptcore 仍链接构建时 glibc，与 GLib 符号是两回事）。

## 七、本版踩坑（入铁律/ pitfalls）

- **Svelte 4 响应式语句不能 return cleanup**（`$: if (…) { const t = setInterval(…); return () => … }`
  编译报 'return' outside of function）——受管 timer + onDestroy 收尾；且回调里读的变量需要以字面实参/
  派生变量进依赖（rotationLength），否则名单 2→3 条定时器不重建。
- **回归断言量尺寸也要过 uiScale**：v094 首跑 5.4 量 checkbox rect.width=27（36×0.75）误判——
  断言布局尺寸一律 offsetWidth（与 3.14/3.20 测量铁律同族，测试代码同样中招）。
- **action 签名**：`use:fn` 的 fn 必须收 node 参数、return `{destroy}` 或 void，return 裸函数报类型错。
- AppState 加字段还需要扫**导出构造点**（nodes.ts 导出单例带 scratchpad 的那处同款带 slogan），
  不只是 normalize/emptyState。
