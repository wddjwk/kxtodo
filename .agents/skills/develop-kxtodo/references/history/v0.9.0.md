# v0.9.0 日程域 + 草稿纸标签页 + 安卓常驻与滑动 + 七项收口

> 这一版的主菜是**第六个领域文件**：日程（`calendar.json`）。代码里一律叫 `calendar`
> （`schedule` 已被定时任务占用），界面上叫「日程」。配套：整页四视图（月/周/三日/日）、
> 三种创建入口、与 todo 条目的双向关联、CLI 与 skill 文档同步。其余是草稿纸标签页、
> 安卓后台常驻与左右滑手势、以及七项体验优化/bugfix。

## 一、日程域（calendar）

### 1.1 命名与地基

- **`schedule` 这个名字不能碰**：定时任务占了 `schedule`/`scheduler`/`ScheduledTasksView`。
  日程的代码标识全链路用 `calendar`：`Domain::Calendar`、`calendar.*` 命令、
  `settings.calendar`、同步范围 `syncCalendar`、前端 store `calendarEvents`、
  CSS 前缀 `.cal-*` / `.calendar-*`。模块注释里写明了这条约定（`ops_calendar.rs` 头）。
- **模型**（`model.rs`）：`CalendarEvent{id,title,details,start_date,start_time,end_date,end_time,all_day,reminders,task_id,created_at,updated_at,extra}`。
  时间是**本地墙上时间**（`YYYY-MM-DD` + `HH:MM`），不做时区换算——日程是「几点开会」，不是瞬时。
  `CalendarView` 枚举 month/week/threeday/day（`parse` 容忍 `3day`/`three-day` 这类写法）。
- **时间归一**（`ops_calendar.rs::normalize_times`）：只给日期 = 全天；定时事件不给结束 = 开始 + 1 小时
  （跨午夜自动进位到次日）；开始晚于结束拒 `CALENDAR_RANGE_INVALID`。
- **挪动语义**（`modify`）：只改开始（日期或时刻）而没给 `--end` 时，结束**跟着平移保持原时长**
  （与日历应用拖动事件一致）；要改时长必须显式给 `--end`。全天事件按天数差平移。
  这条语义是 CLI 集成测试逼出来的：第一版「只改开始超过原结束就拒」把「把周会从 9 点挪到 14 点」
  这种最普通的操作拒掉了。
- **提醒**：复用任务的 `Reminder` 枚举（`Absolute` / `BeforeDue`）。新规则必须是未来时刻
  （`REMINDER_IN_PAST`），同瞬时去重。全天事件的「开始前 N 分钟」按当天 09:00 折算
  （`ALL_DAY_REMINDER_CLOCK`）。提醒引擎（`reminders.rs::plan_calendar`）与任务提醒共用一条
  500ms 节拍与同一份 `runtime/reminders.json` 台账（不同步、过时不补发）。
- **详情插图**走伪条目 `CALENDAR_IMAGE_NODE = "calendar"`（`img/data/calendar/`），
  随「同步数据」范围走；`ops_storage` 的引用盘点与可清理目录都接了它。

### 1.2 同步全链路（diary 是样板）

`model.rs` → `repo.rs`（Domain/layout/load/write/ensure_initialized/backup 六文件）→
`merge.rs`（Scopes + stamp + payload + extract/apply + **settings 共享子集加 `calendar` 外观块**，
`view` 刻意**不**进共享子集——视图偏好是本机状态）→ `engine.rs` 五处（拉取分桶 / 合并事务 /
对账水位 / 推送抑制 / resolve_conflict）+ `scope_signature` 六段 → `host.rs` 事件 match →
`core.rs`/`cli.rs` 的 schemaVersions → `lib.rs::core_snapshot` 的 `wanted("calendar")` +
`put_snapshot_domain` → 前端 `CoreSnapshot` / `applySnapshot` / `normalizeCalendarEvent(s)`。
`extract_entities` 的签名因此变成 **8 参**（calendar 在 ledger 后），merge.rs 的单测与
server 的 sync_e2e 都跟着补了实参。

### 1.3 视图与交互

- `CalendarView.svelte` 与 LedgerView 同构（整页覆盖、移动端历史栈一层）：头部 = 返回箭头 +
  `CalendarClock` 图标 + 「日程」 + 右上**段控四钮**（月/周/三日/日，同记账的段控形态）+ ⋯ 菜单
  （ListMenu 的 `calendarMode`：外观区在、导出导入区隐藏）。区间条 = 今天 / 翻页 / 标题 / 现在；
  月视图的标题可点（MonthPopover）。
- **周/三日/日**走 `CalendarTimeGrid.svelte`：`grid-template-columns: var(--cal-gutter) repeat(var(--cal-days), minmax(0,1fr))`；
  空白处鼠标拖动框选时间范围（15 分钟吸附、`cal-drag-preview`），单击空白 = 默认 1 小时；
  事件块可拖动整体挪、上下缘拖动改时长；跨天事件按天切段、午夜结束折到前一天 24:00；
  重叠簇内贪心分列（**链式重叠复用列**：a–b 重叠、b–c 重叠但 a–c 不重叠时 a 与 c 共列）。
  今天列有一条「现在」红线；打开时滚到 `min(now, 08:00) - 1h`。
- **月视图** `CalendarMonth.svelte`：42 格；格内芯片 = 主题色圆点（全天 = 实底），超过 3 条收「+N 更多」
  跳日视图；点格空白 = 建当天全天、点日期号 = 开日视图、点芯片 = 编辑、右键 = 事件菜单。
- **编辑器** `CalendarEditor.svelte` 与 DiaryEditor 同构：标题 / 全天勾选 / 起止 DatePicker /
  提醒芯片（预设 0/5/15/30/60/1440 分钟 + 自定义绝对时刻）/ 关联条目芯片 / CodeMirror 详情。
  改开始自动平移结束（保持时长）；Esc 或点遮罩 = 保存并关闭（全空则放弃）；显式「保存」总是创建。
- **三种创建入口**：① 右下 FAB → 编辑器；② 视图空白（月 = 当天全天，周/日 = 拖选时间段，
  点区块中心进编辑）；③ todo 条目右键「添加到日程」（预置 dueDate/dueTime/全=无时刻/taskId）。
  已关联的条目右键变「打开日程」；卡片左侧显示 `CalendarClock` 图标（黛紫 `#7c5cbf`，
  不随页面主题变色），网格列戏法与置顶图钉同一套（`workspace.css` 的列组合全枚举）。
- **双向详情**：`updateCalendarEvent(details)` 会连带 `updateTask(markdown)`；反向
  `saveTaskMarkdown` / `updateTask` 挂钩 `syncTaskMarkdownToLinkedEvents`，**等值收敛**不打乒乓。
- **图标区分**（用户点名）：「计划内」= 普通日历 glyph（`IconGlyph "calendar"`），
  「日程」= lucide `CalendarClock`（日历 + 时钟）。两个都叫日历图标会撞。
- **老用户导航注入**：`navItems` 是本机设置、用户隐藏过的行不许塞回。用一次性 localStorage 标记
  （`kxtodo-nav-calendar-seeded-v1`）+ `insertCalendarNavItem`（插在「收藏」后）：
  没标记的老安装补一行并落盘、写标记；有标记就再也不动。回归两个方向都钉了。

### 1.4 Svelte 反应性教训（本版最重要的一条）

`{@const items = cellEvents(date)}` 会把响应式依赖**藏进函数闭包**：键控 each 块看不到
`events` 这个 store 依赖，store 更新后整块不重算——症状是「月视图芯片不随新建/删除刷新」，
而周视图（模板里直接引用）正常。修法：模板里**直接内联**纯函数调用
（`monthCellEvents(events, date)`），或像 TimeGrid 的拖动预览那样用 `$:` 派生
（`renderedColumns`）。**函数调用形式的 {@const} 只允许依赖全是字面常量。**

## 二、草稿纸标签页

- 数据形状从单段 text 改成 `Scratchpad{tabs:[{id,name,text,updated_at}],active_tab_id,updated_at}`，
  仍是**整体 LWW 的单例实体**（kind `scratchpad`），同步语义不变。
  加载时 `fold_legacy_text()` 把旧版的顶层 `text` 折进 `tab-1`——与 ledger 的
  `fold_legacy_images` 同一性质的唯一兼容例外（用户真实数据不能丢）。
- `gui.set-scratchpad` 收 tabs 数组（id 去重、name 截 40、activeTabId 校验）；
  merge.rs 的 scratchpad 载荷改成 `{tabs, activeTabId}`，apply 整份覆盖 + 旧版 text 折叠。
- 界面：单页**不渲染标签栏**（与旧版单页草稿纸一模一样）；加号在子页头部 ⋯ 左侧
  （`scratchpadNewTab` store 递话）；默认名 = 现有纯数字名最大值 + 1 且**跳过已占用**
  （把「2」改名成「会议」后再新建不能撞回「1」）；点激活页 = 改名；悬浮右侧露出 X（16px 定宽占位，
  露出不露出不引起宽度跳动）；右键 = 关闭当前/其他/右侧；宽度 `flex: 1 1 0` + min 84/max 200
  （移动端 76/168）左对齐、放不下横向滚动（滚动条隐藏）。
- **落盘纪律**：文本输入防抖 5 秒，结构变更（新建/改名/关闭/切换）立即写；flush 用
  「合并后的 tabs + activeTabId」签名与 store、与上次写入**双重比对**，没变一个字节都不写——
  否则每次打开草稿纸都会白抬一次 data 域 revision、灌一条审计。
- **光标残留**（顺带整治）：缩放壳 + GPU 合成下 WebView 偶发把旧光标栅格化残影留在原位。
  兜底 = 点击后「scrollTop ±1」+ 一帧 `opacity: 0.999` 强制重绘（不用 translateZ：
  临时提升合成层在缩放壳里会闪一下重采样）。真机偶发伪影，桌面浏览器复现不出来，
  未验证清单点名安卓真机。

## 三、安卓后台常驻（前台服务）

- `KeepAliveService`：**不做任何业务**，只是一张「进程还在前台组」的门票——Rust 侧的
  500ms 调度/提醒节拍与同步引擎本来就在进程里跑（`init_mobile_core::start_scheduler`），
  进程被系统收掉才是一切停摆的原因。`START_STICKY` + SharedPreferences 存开关与标语，
  被系统重建时不依赖 WebView 还活着。
- manifest：`FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE`，service 报
  `foregroundServiceType="specialUse"` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 说明文案
  （Android 14+ 强制）。通知渠道 IMPORTANCE_LOW、ongoing、标语可自定义
  （默认「今天有什么要做的吗~」，`features.keepAliveNotice`，空串回落默认）。
- **设置是本机偏好不进同步**（`features.androidKeepAlive` / `keepAliveNotice`，
  四处对齐：model.rs / ops_config.rs / types.ts / defaults.ts）。
- 对账三处：设置变化（App.svelte 的一条 `$:` → `reconcileKeepAlive`，桥没就绪按 500ms 重试
  最多 40 次——token 由 MainActivity 反复注入，冷启动头几秒可能还没进主 frame）、
  MainActivity.onResume（进程重建 / 后台启动被 Android 12+ 挡掉后的补票）、服务自身 START_STICKY。
- **提醒在后台也要能响**：`MobileBackend::show_notification` 改成**先原生投递再回落前端**——
  通知插件的 Rust 侧在安卓上直接走 JNI 发系统通知，不需要 WebView 在场；权限没授予时原生投递
  失败，回落到前端那条路（它负责申请权限 + 失败降级 Toast），两条路不会各发一次。
- 设置页只在安卓显示这一块，并照实说明：没通知权限时服务仍在跑但通知看不见；
  厂商省电策略仍可能收掉进程（白名单能提高存活率）。**本地无真机，常驻与通知只验到编译与
  manifest 合并（debug APK 构建通过），真机行为在未验证清单点名。**

## 四、安卓左右滑手势

- `swipeRow.ts`（纯函数 + action）：**方向锁** `swipeLock`（横向要压过纵向 1.4 倍且过 8px slop；
  两边都不占优时返回 none 继续等，不抢手势）；过阈值后阻尼 0.4 并封顶。
- 右滑：渐进露出红色删除块（宽度 = 让出的那条），过阈值松手即删；阈值前松手弹回。
  就绪时红块加深一档给明确信号。**不做「拖到就删」**：松手才删是唯一能取消的时机。
- 左滑：`置顶/取消置顶` 与 `编辑` 两块**同时**露出、随同一个 `--swipe-reveal` 一起缩放
  （不是抽屉式一块接一块）；过阈值松手停在该处等点击（`swipe-open`，pointer-events 打开），
  点动作 = 执行并收回、点卡片 = 只收回、点别处 = cardOverlays 的那一份 document pointerdown 收回。
  同一时刻只有一行露出（`revealedSwipeRow` 模块级 store，与日期浮层/露出删除叉同一套收敛口径）。
- **坐标两套**：手势量 clientX = 视觉像素（dp），`--swipe-x` 要写布局像素（translateX 会被壳
  再乘一次 uiScale，默认 0.75）——不换算的症状是卡片只跟到手指的 75%，越滑越脱手。
  与 v0.8.5 VirtualStack 量高是同一个坑，写进了铁律。
- **与既有手势的分工**：pullrefresh 加了同一把方向锁（横向占优当场放弃下拉）；longpress 的
  10px 移动容差自己会放手；滑动后补发的 click 用 `isSwipeSuppressed()` 吞掉（卡片的 click 与
  markdown 的 click 两处都判）；展开态的卡片不接管横滑（长文档里的横滑留给文本选择）。
- 回弹曲线 `cubic-bezier(.2,.8,.2,1)` 240ms；拖动期间 `.dragging` 关 transition。
  **transform 只在 `data-swipe="left|right"` 时挂**：常驻 transform 会让卡片成为 fixed 后代
  （日期浮层）的包含块，把浮层落位整体挪走。
- 下拉同步的收尾动画补了：松手后提示条高度弹回 0 / 收到同步中的 58px（`.releasing` / `.dragging`）。

## 五、七项体验优化与 bugfix

1. **代码块滚动但不显示滚动条**：真根因是 highlight.js 自带 `.hljs { overflow-x: auto }`——
   真正滚的是 `code`、滚动条画在 code 上（全局 `::-webkit-scrollbar` 还给它一条灰轨），
   而外层 `pre` 永远不滚。修法：`pre code.hljs { overflow-x: visible }` 把滚动交还给 pre
   （单一滚动容器），pre 与 code 的滚动条都藏掉（`scrollbar-width: none` +
   `::-webkit-scrollbar { display: none }`）。
2. **固定区三级菜单被挡**：二级面板是 `overflow-y: auto` 的滚动容器，绝对定位的三级面板
   （「添加固定 → 工具箱内的工具」的工具清单）整块被裁掉看不见。修法：深度 ≥ 2 的子菜单改
   **fixed 定位**脱离裁剪祖先（`MenuItem::placeFixedSubmenu`，坐标按壳缩放换算、贴父项右缘、
   右缘放不下翻左、上下钳在壳内——与日期浮层同一套 popoverFrame 口径）；祖先面板一滚动就收起
   （fixed 面板会漂）。限高态的手风琴与移动端钻入式特异性更高，不受影响。
3. **定时任务角标只统计调度中的**：`buildListCounts` 的 scheduled 分支从 `tasks.length`
   改成 `filter(enabled).length`。
4. **剪切板同步**：
   - 图片被识别成文件——安卓 `contentResolver.getType(uri)` 对部分提供者为 null 就落文件分支，
     补四级兜底（resolver → 复制方在 ClipDescription 里登记的 mime → 扩展名 → 前 12 字节魔数）；
     桌面 CF_HDROP 优先会把「截图工具连临时文件一起塞进来」的复制判成文件，改成
     「单一图片文件 + 剪切板同时有位图表示」才按图片同步（资源管理器复制文件不带位图，仍走文件）。
   - **取消 HTML 选项，html 当文件处理**：设置里 `types.html` / `limits.htmlMb` 与界面的 HTML 档
     整块删除；读取端（桌面 + 安卓）把 html 折成一个 `clipboard.html` 文件进 files 通道
     （安卓写固定路径的缓存文件保证签名稳定不重发）；接收端收到老对端的 html 段也落盘成
     `.html` 文件（吃 files 的上限）。线上永远只有「文本 / 图片 / 文件」三档。
   - 安卓保存位置：新增**打开文件夹**（图片目录开相册集合——MediaStore 的 Images 集合永远有
     Activity 接；其余目录把 FileProvider 目录 URI 交给 DocumentsUI，没人接就 Toast 明说）、
     **选择路径**（安卓作用域存储只允许应用用路径写自己的外部目录，所以给
     下载/文档/图片/影片 四个真实可写候选的菜单；桌面仍是系统目录对话框）、**默认**（恢复默认位置）；
     路径显示从单行 input 换成两行可折行 textarea（`word-break: break-all`），长路径不再藏头露尾。
     收到的图片另经 MediaStore 插入 `Pictures/kxtodo` 一份（10+ 免权限，相册立刻可见；
     9 及以下要运行时写存储权限，没给就提示）。
5. **存储空间说明精简**：主视图只留「名字 + 字节数」两列；逐项解释、分项合计、可释放明细与
   清理范围全部收进 ⓘ 展开的灰底卡片（与剪切板工具的 ⓘ 同一套形态）。
6. **截止排序的无日期组**：沉底的那一组内部从「交给插入顺序」改成按创建时间由近及远
   （新建的排第一个），与方向无关；有日期的整块仍在上面。单测钉了两个方向 + 混排。
7. **剪切板工具页偏左**：`.clipboard-page` 补 `margin: 0 auto`（与 `.transfer-page` 同一条口径）。
