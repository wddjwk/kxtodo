# v0.8.2 版本档案（v0.8.1 的收尾：全是修复与加固，零新需求）

> **这份文件是什么**：v0.8.2 的完整改动档案。这一版**没有一条新需求**——13 条全是 v0.8.1 没做完的事与它新引入的 bug，外加读代码/读 git 时顺手挖出来的一批。
> **什么时候读它**：改首帧缓存（appearance / profile / features / state 四件套）/ 两阶段 markdown 渲染 / 写命令的 revision 记账 / 超链接增强 / 浮层的返回键层级 / 编辑器列表缩进 / markdown 任务项渲染之前；排查「点一下先白一块」「设置拨了画面不动」「冷启动闪一下」「返回键把底下的页面弹掉」这类症状之前。
> 当前生效的规则以主题文件为准（`frontend.md` / `invariants.md` / `ui-patterns.md` / `ledger.md`）；这份档案留的是「错的行为长什么样、为什么错」。
> v0.8.1 见 `v0.8.1.md`，v0.8.0 见 `v0.8.md`。

## 一句话

v0.8.1 的方向是对的（把成本从「折叠态白跑」挪走），但有几处**挪错了落点**：长卡片展开让帧期间画的是折叠态内容，用户看到的是「先展开一个空块再蹦出字」；一次 `config.set` 会让 `appSettings` 换两次身份，图表动画因此重启（饼图掉帧）；首帧缓存只缓存了外观与资料，**数据与特性开关各走各的**，于是缓存反而放大了闪烁面。另外挖出一条从 v0.7.3 就存在的硬 bug：`normalizeTask` 没有 `dueTime` 字段，core 模式下任何一次快照刷新都会把任务的时刻抹掉。

## 二、读代码时顺手挖出来并修掉的（用户没报）

- **超链接增强不可逆**：`enhanceLinks` 只会往上加，从不退。档位从「卡片」拨到「不渲染」时，已经渲染出来的卡片**永远留着**（markdown 有记忆化，`{@html}` 拿到同一个字符串根本不动 DOM）——设置拨了、画面不动，要等用户改正文才变。抓取在途时拨档还会把用户刚关掉的卡片又画上去。修法：`cardOriginalAnchor` / `titleOriginalText` 两张 WeakMap 留退路（卡片存**原节点**，属性与文字原封不动放回原位），`revertUnwanted` 在收集 anchor **之前**先退，`applyTo` 落地前**重读当前档位**。
- **首帧拿默认设置做不可逆的 DOM 决定**：状态缓存让卡片在第一帧就画出来，而开关还没水合 → `linkRender` 用默认的 `card` 建出卡片，水合后拨到 `off` 也退不掉（正是上一条的放大器）。这条是 v077 回归里「关掉开关后裸链接保持原样」红掉才暴露的。修法：开关进首帧缓存 + 增强可逆，两条一起才闭环。
- **`renumberOrderedList` 连续同级计数缺陷**（v0.8.1 遗留）：嵌套块之后回到外层，编号从 1 重新开始；松散列表的续行会打断计数。改成按**缩进层级**计数的 `Map`，回浅层时清掉更深层的计数。
- **`indentListItem` 反缩进后越界**：dispatch 之后拿旧的 `range.from` 调 `lineAt`，文档变短时越界抛错，整段重编号被跳过（表现是 Shift-Tab 退回外层但编号不接续）。`anchorLine` 必须在 dispatch **之前**取。
- **标签自定义色写回 core 退灰**：`actions.ts` 三处把 Tag 序列化成 `color:text`，`custom` 的 `hex` 整个丢了 → core 存成无 hex 的 custom → 渲染端降级灰。统一走 `tagParam()`（`custom` 且有 hex 时用 hex 当颜色令牌，core 的 `parse_tag_input` 认 `#rrggbb:文字`）。
- **两套回归在空账本上跑**：`v077`/`v078` 的 `seedBook` 写的是 `kxtodo-ledger-book`，而应用读的 legacy 键是 `todo-note-ledger-v1`——「资产趋势」「换月手势」那几项一直是空数据在跑。改对键之后暴露出两处**断言前提**也跟着变了：当前月有数据时「程序化滚到底」本身就会触发换月（一跳被算成两跳），只有两个分类时没有二级搁板可展开。一并修好（基准月在滚动落定后再读；种子给餐饮补两个二级分类；两处 `day()` 改本地日期，`toISOString` 是 UTC、凌晨跑会差一天）。
- **标签配色补 `pink`**：`TagColor` 前后端同步加（`types.ts` / `tagColors.ts` / Rust `model.rs` 的 `as_str`+`parse` / `ops_task.rs` 的错误消息），CSS 三处（`.task-tag.tag-pink`、`.tag-preset.tag-pink`、swatch）。skill 文档与 `SKILL_VERSION` 3 → 4。
- **人民币大小写反向识别**：`fromChineseYuan`（简繁体都认：九/玖、两/兩、貳/贰、参/參…；亿/万分级、节内零占位、「拾伍」十位无数字按 1、结尾「整/正」剥掉、有「元」但整数段为空回 null）+ `formatYuanNumber`。工具页按首字符自动判向（不是数字就走反向）。

## 三、编辑器与 markdown 任务项的当前口径（需求 9）

- **Tab / Shift-Tab**：整行缩进两格，**松散列表的续行跟着一起动**；无序标记按层级轮换 `-` → `*` → `+`；有序列表按缩进层级重排编号；光标落在最后一个被改行的**行尾**（早先落在行首，接着打字就插到标记前面）。不在列表里时返回 false 落回 `indentWithTab`。
- **Enter**：列表项里续下一项；**标记后没有文字**时回车 = 向左缩进一级，顶级则清掉整行标识（都不新增行，光标跟着走）。必须用 `Prec.high(keymap.of(...))` 压在 `markdown()` 自带的 Enter keymap **之前**（扩展顺序在前的优先）。
- **多级 checkbox 缩进**：下一级的勾选框落在上级**文字起点右侧约一个空格**。`padding-left: 3em` = 1.4em（把 `margin-left: -1.4em` 拉回来）+ 0.95em（框宽）+ 0.4em（框与文字间距）+ 0.25em（那一空格）。
- **勾选框**：`0.95em`、`margin: 0 0.4em 0 0`、`vertical-align: -0.1em`（比字略小、行内垂直居中）；`li > p` margin `0.2em`（首尾归零）让列表行距与正文一致。
- **点击勾选框只划当前行**：见一表第 9 条。做不到「只划当前行」就去掉删除线是当时给的退路，实际做到了。

## 四、这一版新增的铁律（已进 SKILL.md 与 invariants.md）

1. **写命令的信封 revision 必须记账**：任何 `coreDispatch` 写操作回来后调 `noteEnvelopeRevision(envelope.meta)`，否则随后的域事件会把同一份数据**再应用一遍**（对象身份变两次 = 动画重启、图表重算、`$:` 全跑）。`gui.*` 命令一律不发域事件，不用记；`task.modify` 这类带 `expectedUpdatedAt` 冲突检测的**刻意不记**（记了会让自己的下一次写入被误判成冲突）。**挡掉域事件那一轮就等于撤掉了「快照兜一致性」**，所以 `setConfig` 改用信封带回的**落盘后权威值**兜（`config.set` 的 data 里有 `value` = 写完从文件读回的值）：与乐观值 `sameValue` 比一遍，不同才再 `set` 一次。core 会 clamp 的字段（`sync.intervalSeconds`/`reconnectSeconds` clamp(5,86400)、三处 `backgroundOpacity` clamp(0,1)）目前前端都夹过同一道界（不可能漂），但**两边各夹一次早晚会对不上**——权威值在信封里，没有理由不用。
2. **凡是参与首帧渲染的设置都必须进首帧缓存**：appearance / profile / features / state 四件套（+ 头像缩略图）。少缓存一样，第一帧就按默认值画、水合后再改回来 = 用户眼里的「闪一下」。缓存写入一律**先 stringify 比对**，值不变一个字节都不写（同步 `setItem` 是同步磁盘 I/O，落在动画帧里就是掉帧）。
3. **命令式 DOM 增强必须可逆**：渲染后对 DOM 做的破坏性增强（换节点、覆写文字）要留退路，且**落地前重读当前设置**——设置随时会变，而 markdown 有记忆化不会重渲，靠重渲来纠正等于永远不纠正。
4. **返回键的测试入口是 `window.kxtodoBackHandler()`**：安卓硬件返回键走的是 MainActivity → evaluateJavascript → 这个函数（返回 true = 前端吃掉，false 才让 WebView 退历史/finish）。测试里直接 `page.goBack()` 量的是历史栈，**问不到浮层拦截器**，也就测不出「返回只关最上层浮层」。
5. **`normalizeTask` / `normalizeNode` 必须逐字段对着 model 过一遍**：core 加字段时前端 normalize 漏一个，就等于「每次快照刷新都把用户的值抹掉」——`dueTime` 漏了两个大版本才被发现，因为它只在「设了时刻 + 触发过一次快照刷新」时才现形。
