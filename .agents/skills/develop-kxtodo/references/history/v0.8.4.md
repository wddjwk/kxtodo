# v0.8.4 版本档案（长列表窗口化 + 传输助手重做 + 交互一致性收口）

> **这份文件是什么**：v0.8.4 的完整改动档案。这一版三块：**长列表窗口化**（日记/任务/分组视图，性能专项）、**文件传输助手按 LocalSend 重做**（设备名 + 常驻在线 + 接收确认 + 文本消息 + 历史）、以及**一批交互一致性收口**（取色器统一预览/保存、工具箱子页头部、固定区拖动、编辑器字体与有序列表、日期面板尺寸……）外加 6 条 bugfix。
> **什么时候读它**：改列表渲染（虚拟化 / `VirtualStack` / `windowing.ts`）前后；改传输助手（`transfer.rs` 的在线会话 / 设备名 / 接收确认 / 文本消息 / 历史）之前；改取色（`colorPreview.ts` / `ListMenu` / 工具箱外观菜单）之前；改编辑器字体与有序列表（`codemirrorSetup.ts` / `markdown-ext.css` 的 counters）之前；排查「列表卡死 / 打开慢」「传输里看不到对方」「点日期整个面板缩窄」「选中日期看不见」「标签面板元素溢出」这类症状之前。
> 当前生效的规则以主题文件为准（`frontend.md` / `invariants.md` / `ui-patterns.md` / `sync.md`）；这份档案留的是「为什么这么设计、错的行为长什么样」。
> v0.8.3 见 `v0.8.3.md`。

## 一句话

性能那条线只动渲染层（store 里永远全量，只决定挂谁），用一份自写的 `windowing.ts` + `VirtualStack.svelte`——**virtua 用不了**：它的 Svelte 包是 runes 组件、item 内容走 `children` snippet，而 legacy 组件给带参数的 snippet 传内容时编译器只产出 `invalid_default_snippet`（Svelte 明确报「Cannot use {@render children(...)} if the parent component uses `let:` directives」）。传输那条线把「一次一发」改成**一个常驻在线会话**（设备名 + 口令常驻 + 轮询房间 + 接听拨入），于是「挑设备发」「接收确认」「文本消息」「设备历史」才成立。交互收口那条线反复出现的同一个根因：**「活值 vs 落盘」两套时机各写各的**（取色四处、日期面板两处、工具箱子页返回两处），这一版全部收成一个来源。

### 顺带修掉的一类：浮层里的 `var(--accent)` 未定义

第 11 条（编辑器日历「选中的那天看不到」）的真相是：`.dp-cell.selected` 是 `background: var(--accent); color: #fff`，而**编辑器对话框挂在主容器之外**（主容器才有 `--accent` 覆盖），裸 `var()` 未定义 → 整条声明失效 → 白字 + 透明底。修法是在 `.app-shell` 上给一次 `--accent` 默认值（比在 100 多处 `var()` 里逐个补回退稳），一处修好所有「浮层里的 accent」。

## 二、长列表窗口化（需求 3–6）

- **只动渲染层**：`store` 里数据永远全量（5000 篇正文进内存无害），窗口化只决定「挂谁」。
- `src/lib/windowing.ts`（纯逻辑 + 13 条单测）：前缀和 / 落点二分 / `windowRange`（上下各 `overscan`，`maxCount` 硬上限）/ `initialCount`（首屏至少 30）/ **滚动锚点**（按 key 还原 `scrollTop`，头部插入新日记时列表不跳）。
- `src/lib/VirtualStack.svelte`（legacy 槽位 `slot="item" let:row`）：上下两段占位撑住总高、每项挂载时同步量一次高度、之后交给共享的 `ResizeObserver`（`measureBus.observeResize`，展开卡片/图片加载都会变高）。`fullBelow`：项数 ≤ 该值时**全量直出**（任务列表用 100 做阈值——小列表虚拟化反而是负担）。
- **滚动容器是父组件 `bind:this` 出来的，监听不能只在 `onMount` 挂**：子组件的 `onMount` 可能先于父组件的绑定赋值跑完，那样监听从来没挂上（症状：滚动条能拖、窗口永远停在开头）。跟着 prop 变化挂/摘。
- 日记列表（`DiaryView` 的 `listRows`）、entry 任务列表（`Workspace` 的 `taskRows`）都用它；日记**分组视图**改成「记展开而不是记折叠」（`expanded` 默认全空 = 全折叠），展开一个年只出月份小标题、展开一个月才挂该月条目。
- 实测（`scripts/perf-bench.mjs` 升级后的口径，5000 日记 / 1000 任务 / 10000 账目）：日记界面打开 154ms、挂载 24 张、堆 74MB、滚 8 屏 0 个长任务；1000 卡 entry 打开 122ms、挂载 31 张。验收线（<1s / <500MB / 无 >100ms 长任务 / <2s）都留了大余量。

## 三、文件传输助手重做（需求 1）

`transfer.rs` 从「一次一发」改成**一个常驻在线会话**：

- **设备身份**：`runtime/transfer-identity.json` 里一把稳定的设备密钥（v0.8.3 每次会话现生成，设备历史里每次都像新设备）。设备名走 `settings.transfer.deviceName`（本机偏好、不进同步子集），发布用同步那份 `directory::publish_name`（`_name` TXT 记录，挂在**自己 EndpointId 的 zone** 上，别人按 id 直接解析）。
- **口令常驻**：`runtime/transfer-code.json`（明文，与 `sync-credentials.json` 同一条先例——它本来就是两人约定的暗号）。启动时若记住的口令 ≥8 位就自动上线。
- **在线会话**（`online_slots`：按数据目录索引的表，生产里只有一个，测试里两台「设备」各带自己的 runtime）：起端点（用稳定身份）→ 发布房间条目 + 名字 → `select!` 同时等拨入与 2 秒轮询（**accept future 不能一次只等 1ms**：QUIC 握完到 accept 返回之间可能超过那个窗口，取消一次就丢一个拨入）→ 轮询结果推 `devices` 事件。
- **拨号要用真正的 `EndpointAddr`**：前端拿到的 id 是 z32 字符串（好看），但 iroh 的 `FromStr` 只认 RFC4648 base32 与 hex——**不要拿 z32 去 parse**，会话里另存一份「z32 → EndpointAddr」的地址表。
- **接收确认**（需求 1.3）：收到清单先推 `request` 事件（对方名字 + 清单 + 总大小），等界面的 `decide`（或「自动接收」开着直接放行），60 秒超时当拒绝。
- **文本消息**：同一条握手，`mode=text`，不落盘、不进保存位置，收完推 `text` 事件给界面的消息卡片（复制 / 保存为 .txt）。
- **同名冲突默认自动重命名** `照片(1).jpg`（不做覆盖），`fileDone` 事件带 `renamed` / `savedAs`。
- **历史**（`runtime/transfer-history.json`，不进同步）：最近 50 条 + 设备名录按 device-id 去重（上限 32 台）。
- **结束帧宽容**：每个文件都已单独确认过，最后的 `end` / `endAck` 只是收尾礼节——对方写完 ack 就释放连接是正常的（发送方读到 `connection lost` 也无所谓），所以给它 5 秒超时、拿不到就当成功。
- 界面照 LocalSend：顶部身份区（设备名 + 口令 + 在线绿点）→ 居中分段滑块（发送/接收）→ 四个大图标（文件/文件夹/文本/剪贴板，移动端 2×2）→ 已选清单 → 单选的设备卡片 → 右下角胶囊发送按钮；接收侧「待命接收中 + 保存位置 + 更改/打开文件夹 + 自动接收开关」；传输中/完成/失败的会话卡片（速度用 EMA 平滑、剩余时间 = 剩余 ÷ EMA、完成后 5 秒自动收起）；历史折叠区。内容列 `max-width: 720px` 居中（移动端单列，修掉 v0.8.3 的宽度超屏）。
- 剪贴板图片：`navigator.clipboard.read()` 拿 `image/png` 的 blob → 分块写进 `runtime/transfer-outbox`（与移动端发送同一条 spool 通道）→ 按文件发。桌面拖放（`getCurrentWebview().onDragDropEvent`）：拖进来的路径先试 `transfer_list_folder`（是文件夹就递归成清单），否则按文件。
- 明确不做（写进需求）：断点续传、多设备群发、Web 链接分享、传输历史云端化、收藏设备。

## 四、交互一致性收口（需求 7–15）

### 取色统一：预览 + 保存（需求 9）

`src/lib/colorPreview.ts`：主题色 / 背景色 / 临期配色**共用一个草稿预览 store**（`scope` = 节点 id / `diary` / `ledger` / `toolbox`，消费端只认自己那一份）。取色只改草稿并推预览（界面立刻变），点「保存」才 `setConfigAction`；「取消」或菜单关掉 = 丢掉草稿、预览回退。消费端：`Workspace`/`DiaryView`/`LedgerView`/`ToolboxView` 的 `mainStyle` 走 `backgroundWithPreview` / `accentWithPreview`，`TaskCard` 的临期配色走 `dueColorsWithPreview`。三个选择器是纯函数（6 条单测）。

### 工具箱子页头部（需求 7）

「返回工具箱」整行撤掉，改成右上角两枚按钮（左 = 返回、右 = ⋯ 外观菜单）。外观菜单复用同一套「草稿 → 保存」：工具页的背景色与主题色存在 `settings.toolbox.*`（core 侧新增的 `ToolboxSettings`，外观进同步共享子集、无 view）。`--accent` 现在由 `.toolbox-view` 自己内联（之前工具箱靠 `var(--accent, #2564cf)` 兜底、主题色不可换），`toolbox.css` 里写死的几处 `#2564cf` 一并换成变量。

### 固定区拖动排序（需求 8）

- 落点**按布局两种算法**：单列按 Y（行内上半/下半），双列/只图标按「同一竖带内比 X」——只比 Y 在双列/图标模式下是错的（双列左右同高、图标整块只有一排）。
- 拖动改成**行实时让位**（`navDragOrder` 预览 + Svelte `animate:flip`），松手才落盘；被拖的行有抬起态（阴影），不再画落点线。整个 nav 列表在单列/双列/图标三种布局下都可用（三种布局各有一条回归）。

### 记账统计（需求 10）

侧段控只剩 支出|收入（「结余」曲线改由图例胶囊切出，复用「侧=结余画三线」的逻辑），移动端把「周」加回来；折线图标题固定「收支趋势」；图例改成三枚可点胶囊（`aria-pressed`，亮 = 该曲线在图上、色块用该侧颜色；灰 = 隐藏，色块走 `var(--dot, #c8ccd2)`——**空字符串的 `--dot` 取不到回退色**，会整块透明）。「最后一条亮着的不许关」——关掉整张图就空了。

### 日期面板（需求 11/12）

- 编辑器工具栏的日期**已经是** `TaskDateReminderPanel`（三入口共用），所以要修的是共用 `CalendarGrid` 的「选中日看不见」（见第一节的 `var(--accent)` 那条）。
- **尺寸稳定**：`.date-picker-grid` 定宽 228px（7 列等分）——不写死宽度时，外层是收缩包裹的容器（右键菜单子面板、编辑器元数据浮层）会按 max-content 定宽，而**选中日加粗**会把某一列撑宽（点哪天尺寸不一样）；`.dp-time-wheel` 同样定宽 228 **定高 219**（= 日历块实际高度），切「日期 ↔ 时间」标签页或切「选择时刻」时面板宽高都不变、上下两行钉住。菜单/编辑器上下文里的面板也从 `width: 100%` 改成 228（收缩包裹的第二个来源）。
- 日记编辑器的日期按钮去掉「勾选框 + 时刻」那一行（日记不需要改时间，与卡片右键「修改日期」同款）。

### 日记/记账头部（需求 14）

搜索从齿轮面板挪成顶部按钮（日记：分视图 / 搜索 / 日记菜单；记账：分视图 / 搜索 / 记账菜单），齿轮直弹各自的菜单（少一层只有两三项的面板）。记账的「分类管理 / 账户与转账」收进记账菜单（`ListMenu` 加了一个 `slot="extra"`——壳保持通用，菜单里有什么由调用方决定），记账菜单去掉「排序方式」。

### 编辑器（需求 15）

- 正文换成**应用的基础字体**（`base.css` 新增 `--font-body`，`editor.css` 同时覆盖 `.cm-editor` 与 `.cm-scroller`——CodeMirror 基础主题给 `.cm-scroller` 写死了 monospace，只改父级不够），与草稿纸同字体、同字号（草稿纸从 `--font-control` 改绑 `--editor-font-size`）。
- 编辑态列表标记不再单独着色（去掉 `tags.list` 的蓝色）。
- **有序列表缩进 2 → 3 空格**（`INDENT_STEP`）：CommonMark 里有序父项 `1. ` 的内容列宽是 3，2 空格缩进去会被当 lazy continuation 摊平——「编辑态看着有层级、预览里全平了」；3 对两种父项都成立，也够不上「≥4 空格 = 代码块」的门槛。第三级回车不递增编号的问题随之消失（同一根因）。
- **渲染态层级编号**用 CSS counters（`counters(kx-ol, ".")` 出 2.1 / 2.1.1，`counter-reset` 每层 ol 各一次）；任务项不画编号（它有自己的勾选框）。

## 五、草稿纸（需求 2）

- 正文从 localStorage 迁进**数据域**（`DataFile.scratchpad { text, updatedAt }`），跟着「同步数据」范围走（**新 entity kind `scratchpad`**，单例 id；`updatedAt` 空 = 没写过，不产生实体）；localStorage 只留作首帧缓存。
- 写入走新命令 `gui.set-scratchpad`（一次落盘 = 一条审计 + 一次 revision），前端防抖从 400ms **拉到 5 秒** + 切后台/关页面前 flush——「退出必保存」不变，台账不被逐键输入灌爆。
- 「正在输入&已自动保存」提示行撤掉。

## 六、这一版的教训（写进主题文件的那些）

1. **Svelte 5 legacy 下，别在 `$:` 语句里依赖「被调用函数里的状态写入」重新调度**。`$: if (cond) void openTool(x)` 里的 `openTool` 第一行写组件状态，不会让别的 `$:` 或模板重跑（`legacy_pre_effect` 的 `set_active_effect(effect.parent)` + `untrack`）。修法不是换写法、而是**去掉那份影子状态**：让唯一真源（store）直接派生渲染。
2. **收缩包裹（shrink-to-fit）的容器 + 内容里加粗/换字 = 尺寸漂移**。日历年月面板、菜单子面板、编辑器浮层都吃过这个亏：要么给内容定宽（`.date-picker-grid`）、要么给容器定宽（`.date-picker-grid` 的宿主）。「点哪天尺寸不一样」的根因就是**选中态加粗改变了 max-content**。
3. **子组件的监听别绑在 `onMount` 的 prop 上**：父组件 `bind:this` 的赋值可能晚于子组件 `onMount`，监听就永远没挂上（症状是「能滚动、窗口不动」）。跟着 prop 变化挂/摘。
4. **accept future 不能短超时反复取消**：`timeout(1ms, accept())` 每次迭代都新建 future，QUIC 握手完成到 accept 返回之间的窗口一旦跨过就被丢掉（症状：发送方报「对方离线」、接收方全程没反应）。用 `select!` 让同一个 future 一直挂着。
5. **iroh 的 id 有不止一种文本表示**：`to_z32()` 出来的东西 `FromStr` 不认（那个只认 RFC4648 base32 与 hex）。跨层传递时要么带上可拨号地址，要么在核心侧查表，别指望 parse 回来。
6. **协议收尾帧要能缺**：逐文件回执已经把「到了没有」答完了，最后那条 ack 只是礼节；对方写完就释放连接是正常的，硬要求它就得到 `connection lost` 这种假失败。
7. **写「预览」要先想清楚退路**（v0.8.2 铁律的延伸）：预览值住在一个按 scope 索引的 store 里，菜单关闭 = 预览作废——不然「在日记页改色把工作区也染上」「退出后界面停在没保存的颜色」这类串页/悬空都会来。
