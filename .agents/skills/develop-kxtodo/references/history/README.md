## 为什么要有这个目录

原 `AGENTS.md`（274 行 / 166,681 字节）里有近一半篇幅是**按版本累积的界面流水账**（v0.4.0 → v0.7.8 逐版「本版改了什么」）。它每轮对话被全量注入，是巨大的固定上下文税，而且越积越难查。搬进 `history/` 之后：

- **SKILL.md 里绝不堆版本流水账**——SKILL.md 只放「当前不变式」与「指路」，长度控制在 500 行以内。
- 当前架构与当前界面约定在 `architecture.md` / `frontend.md` / `ui-patterns.md` / `ledger.md` / `sync.md` 等**按主题**组织的文件里。
- 「这一版为什么这么改」「上一版是怎么做的、后来被谁推翻了」这类**追溯性问题**才来 `history/`。

## 怎么用

1. **要改某个界面/行为**：先读主题文件（`ui-patterns.md` / `ledger.md` / …）。主题文件里的正文本身就带着版本标注（如「**折叠态标题的省略号规则（v0.6.3）**」），当前规则与它的来历在一起，不用来回跳。
2. **主题文件不够、要看某一版的完整改动清单**：来对应版本的档案，表格里「这一版的改动」一列是 AGENTS.md 原文的粗体小标题（一字未改），「现在住在哪」一列告诉你全文搬去了哪个主题文件的哪一节。
3. **v0.7.3 之后的记账与全局打磨**：`v0.7.0-v0.7.4.md` 与 `v0.7.5-v0.7.8.md` 里带**全文**（那些 ①②③… 编号的逐版打磨清单是原 AGENTS.md 里最长的几块，很多当前界面细节**只**在那里，例如：条目两行卡片、编辑器圆形分类网格与内联二级搁板、统计双段控与结余三曲线、钻取独立配色、自定义账户类型与直设余额、资产趋势图、移动端浮层超屏的真凶、半屏抽屉滚不到底、输入法跟随、超链接渲染六条打磨）。**改记账界面之前必须先读这两份。**
4. **v0.8.3 加了两个成体系的能力**：任务提醒（`reminders.rs`、`runtime/reminders.json` 台账、时钟跳变不补发、看门狗不退出、移动端通知交回前端）与文件传输（`transfer.rs`、口令派生房间与握手令牌、ALPN 必须与同步不同、`safe_join` 守路径）。要动这两处、或要动「日期与提醒」面板与它的三个入口、工具箱的固定与拖动、markdown 行首空白与任务项映射，先读 `v0.8.3.md`——那里还记着 11 条 review 的采纳/不采纳理由（比如「直达表单返回该整层关」为什么保留）。
5. **v0.8.2 修的是 v0.8.1 的收尾**：首帧缓存四件套（appearance / profile / features / state）、两阶段 markdown 渲染、写命令的信封 revision 记账、超链接增强的可逆性、浮层返回键的层级、`normalizeTask` 漏字段——想动这几处先读 `v0.8.2.md`，那里记着「改之前错在哪」与五条新铁律的来历。
6. **v0.8.1 修的是 v0.8.0 的收尾**：外观/资料缓存、懒加载失败路径、返回键守卫的 dispose、配对时的设置时间戳——想动这几处先读 `v0.8.1.md`，那里记着「改之前错在哪」。
7. **v0.8.0 是非功能版**：当前的性能格局与同口径约束（渲染记忆化、`fullHtml` 懒渲染、按域快照、审计白名单、五文件备份、图片体积闸、CLI 分页与 jq、62 天门槛）以主题文件为准，但「**错误的旧行为是什么、为什么错、哪些方案明确决定不做**」只在 `v0.8.md`——想推翻某条约束前先查它的「明确决定不做的」清单。

## 每轮开发结束时往这里写什么

见 SKILL.md 的「自我迭代条款」。简言之：本轮新的**界面细节与本版改动** → `history/vX.Y.md`（当前正在进行的那个大版本）；新的**不变式/铁律** → SKILL.md 第 4 节 + `invariants.md`；新的**平台坑位** → `pitfalls-*.md`；**架构变化** → `architecture.md`。
