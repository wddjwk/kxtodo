## 一句话

两轮改判之后定案的**浮层定位只有两条分支**（下方放得下就左上角贴鼠标、放不下整个翻上让下边缘贴锚点，右键菜单再横向镜像；**「下方限高 + 内部滚动」被真机打回，删掉**）；**统一取色盘补齐三件**（缩放壳里让 iro 的视觉尺寸==布局尺寸、确认前冲刷 pending 预览、同入口重开作废旧会话）；**工具箱与工具子页各有一套三点菜单**（复用 `ContextMenu` 的点锚定与 `MenuItem`，每个工具的颜色单独存 `toolbox.toolAccents/toolBackgrounds`）；再修两处正确性（搜索时间戳走 `Date.parse`、中间批封顶；时刻双轨 `overscroll-behavior: contain` + 定宽）。

## 一、浮层定位契约（`popover.ts::placePopover` 终裁）

### 1. 两轮改判的经过（为什么最后只剩两条分支）

- **第一轮**（v0.8.6）：`spaceBelow >= 120 && spaceBelow >= spaceAbove` 才留在下方，否则翻上。真机症状：鼠标在视口中下部时上方恒大于下方，菜单比下方可用多 1px 就整个翻上去，**鼠标动 1px 菜单跳 ~400px**（「不跟手」的真身）。
- **第二轮**（v0.8.6 的修复）：加了「下方还留得出 `POPOVER_MIN_HEIGHT_PX` 就原地限高 + 内部滚动」。跳变没了，但真机立刻打回：**「菜单出滚动条这太蠢了」**。
- **终裁（本版）**：删掉整条限高分支与 `POPOVER_MIN_HEIGHT_PX`/`minHeight`，只剩两条——下方放得下 → 左上角顶点贴鼠标（盖住唤起按钮会让「点按钮」变「点菜单」）；放不下 → 整个翻上、下边缘贴锚点。**唯一滚动兜底是「上下都放不下（浮层比视口还高）」时的 `maxHeight` 钳制**。

### 2. `mirrorXOnFlip`

右键/长按菜单翻上时横向镜像成「右下角顶点贴鼠标」。默认开的依据是**结构性恒等**：`xAlign:"right"` 时 `left` 与镜像后是同一个表达式 `clampLeft(anchor.x - width)`，所以 `ContextMenu` 直接把 `mirrorXOnFlip` 默认成 `true` 覆盖全应用，8 个调用点不用逐处加 prop；按钮锚定的浮层（列表菜单、日期浮层、取色盘）不开——它们的锚点是按钮边缘，镜像后对不上（`placePopover` 默认 `false`）。
**别给任务菜单补 `xAlign="right"`**：那会把契约①的「下方左上角贴鼠标」也改成右对齐——①②不能同时满足，镜像交给 `mirrorXOnFlip`。

### 3. 量高的单位口径（第 4 次踩同一类坑）

三处浮层（`ContextMenu` / `ColorPickerPanel` / `TaskCard` 的日期浮层）都把 `scrollHeight` 又除了一次 `uiScale`。`scrollHeight` 本就是**布局像素**（不受 transform 影响），只有 `getBoundingClientRect` 才要除。多除一次把菜单量高 33%，翻上后底边落不到锚点（实测差 82px）。正确写法：`Math.max(rect.height / scale, scrollHeight)`。

### 4. 调用方约定（没有变）

入参/返回都是**逻辑像素**：调用方把 `getBoundingClientRect()` 除以 `uiScale` 之后再进、结果原样写进样式。锚点须在视口内（界外锚点无夹回语义，也不该有）。落位前先 `visibility: hidden`、量尺寸等**双 rAF**（首帧内容未定宽，钳制会算错）。

## 二、取色体系（统一取色盘）

### 1. 语义总纲（三入口共用，本版把宿主菜单里的第二套按钮删了）

拖动 / 手输 HEX/RGB = **只改草稿 + 实时预览**；**确认 = 落盘**；取消 / 点浮层外 / Esc = 丢弃草稿 + 预览回退。**落盘按钮只存在于色盘面板上**——清单里的 5 处旧 `ColorDraftActions`（ListMenu ×3 + ToolboxView ×2）连同组件本体一起删掉：确认挪进色盘之后，旧的「保存/取消」与新确认并存且语义重叠（真机打回：「说好的确认加到色盘区域，怎么原始的保存取消还在」）。

### 2. 色盘几何（缩放壳里挂第三方指针组件）

iro 的指针数学是「光标**视觉**坐标 ÷ svg **布局**宽」——外壳 `transform: scale(uiScale)` 让两个数差一个缩放比，拖动时把手指脱靶（实测偏移 × (1−scale)，44px；离左上角越远偏得越多）。**修法三件套缺一不可**：

1. 宿主内加一层反缩放：`.kx-color-canvas-scale { transform: scale(calc(1 / var(--ui-scale, 1))); transform-origin: top left }`，iro 挂进这一层（不是直接挂宿主）；
2. iro 宽度传**视觉口径** `Math.max(120, Math.floor(host.clientWidth × uiScale))`——svg 的视觉宽 == 布局宽，iro 的分数精确；
3. 宿主高度显式补偿：挂载与每次 resize 后 `host.style.height = picker.base.offsetHeight / uiScale`（svg 布局盒 ≠ 视觉盒，不补会把面板下方字段区压住）。

配套：`.kx-color-canvas { overflow: hidden; place-items: start stretch }`（裁剪边在任意缩放下数学上精确落在色盘视觉边上；`place-items: center` 在 uiScale > 1 时引入左偏）；resize 的宽度比较一律用 `picker.base.offsetWidth`（布局对布局，别拿 rect 跟 clientWidth 比）；`.kx-color-canvas { touch-action: none }`（安卓拖色不滚页面）；面板 `max-width: calc(100vw - 24px)` 兜底窄屏。

**测试方法的教训**：v0.8.6 的回归脚本拖动断言只数 `previewWrites` 次数与 hex 结果，**从不比对把手指落点**——拖歪 44px 颜色照样算对、测试照样全绿。现在补了几何断言（mousedown 到 SV 盒 80%/70% 处 → 读 handle 圆心 → 与光标差 < 3px，dev 环境 uiScale=0.75 正好覆盖缩放场景）。

### 3. 确认前冲刷（结构性丢改动）

改了 HEX/RGB 输入框后**直接点「确认」**，颜色必须生效（此前落旧值）。机制：面板预览全部走 rAF 合帧，`confirmColorPicker()` **同步**把 store 置 null 再调 onConfirm → 还没跑的 rAF 醒来被守卫丢弃；而 HEX/RGB 的提交挂在 `on:blur` 上——**确认点击自己的 mousedown 就是那个 blur**，rAF 是确认点击自己排进去、又被它自己的 click 作废的，**等再久也没用**（不是窄窗口竞态，是结构性缺陷；真人手里要「按下时长不足一帧」才中，但代码路径错误不靠概率免责）。

修法 A+B：
- **B（治本）**：面板 `confirm()` 先 `flushDraftsIntoPicker()` + `flushPendingPreview()`（`cancelAnimationFrame` + 同步 `onPreview(pendingColor)`）再 `confirmColorPicker`。「确认前先落地最后预览」是面板的职责，8 个消费端一起受益；
- **A（加固）**：消费端的落盘函数改用**面板传回的实参**（`saveUiColor(color)`），别读可能与落盘时机脱节的草稿。多档位消费端（临期色四档）单靠实参接不上档位，由 B 覆盖其语义。

### 4. 同入口重开

`openColorPicker(request)`：**有 current 就先 `current.onCancel()`**（此前只在「换了不同 key」时作废，同一入口重开时旧草稿/预览会带进新会话）；并给 key 追加会话序号 `${key}#${++nonce}`——面板的重挂判据是 key 串比对，不加序号同 key 重开面板不重挂、输入框还停在已作废的旧草稿上。key 只是面板与消费端之间的不透明身份串，没人解析它。

### 5. 吸管（找回丢失的能力）

v0.8.5 的吸管是原生 `input[type=color]` 弹的**系统选色器自带**的——代码里从来没有过，v0.8.6 换 iro 时静默丢了。现在面板操作行加「吸管」按钮，`'EyeDropper' in window` 才渲染（Windows WebView2 = Chromium ✓；Linux WebKitGTK / 安卓无此 API → 按钮不渲染，别硬上）；点击 `new EyeDropper().open()` → `sRGBHex` → `picker.color.set(...)`（走既有 `color:change` 链路：同步输入框 + 预览，确认才落盘）；`AbortError`（用户取消）静默。
**通用教训**：原生控件换自绘之前，先盘「这个能力是不是系统给的」。

### 6. 临期高亮色的**系统视图双回退**

真机打回：「我的一天里改临期色 → 不能保存、不能预览」。根因是**编辑端与消费端的键不是同一个**：系统视图（我的一天/计划内/收藏/定时任务）里编辑端 `dueColorKey()` 返回**视图节点 id**，写进 `dueColors["my-day"]`；而 `TaskCard` 读的是**卡片自己条目的键** `dueColors[task.nodeId]`。两头各自正确、对不上号——**条目页两头键一致所以完全正常**，排查时别被它骗过去。

修法（对齐主题色语义「我改的就是我看到的」）：`colorPreview.ts::dueColorsForCard` 双回退——自己条目的配置优先（含自己的草稿）；没配过、且 `selectedNode` 是系统视图时跟视图的配置走，预览在同一条链上叠（先叠自己条目的草稿，再叠视图草稿）。条目页行为完全不变（单测钉住五种情形）。

### 7. 预设色块编辑器：即输即生效

旧交互（被打回）：右键色块弹编辑器（名称 + 颜色 + 保存/取消），从编辑器色块打开的色盘**不推工作区背景预览**、取消什么都不回滚。三宗罪：色盘拖动背景不实时更新、双保存按钮扰人、取消不还原。

新交互（无保存/取消按钮）：
- **名称输入完立即生效**：`on:input` 进草稿 + **停输 300ms 自动提交**（写进 `themePresets`）；失焦与菜单关闭（`discardColorDrafts`）兜底再提一次。**不逐键写盘**——`setConfigAction` 是原子写，连续敲字会打爆；
- **颜色输入框合法 HEX 即写** `themePresets` 并应用为当前背景；
- **编辑器色块打开的色盘**：`onPreview` = 编辑器草稿 + **背景草稿双写**（走 `colorDraft.background` + `pushColorPreview` → 工作区实时染色）；`onConfirm` = 写进 `themePresets` 并应用为当前背景（名称草稿一并带上）；`onCancel` = 编辑器草稿回**已存值**（`themePresets[i].color`，不是「打开编辑器那一刻的颜色」——即输即生效之后这两者会分叉）、背景预览清掉、工作区回到落盘值；
- 点任意预设色块 = 选它作背景并**结束编辑**（名称草稿先补提）；「恢复默认配色」也会先把编辑器收掉（它会把 `themePresets` 整份换掉）。

### 8. 预设色块的 CSS（两轮坑，别只修一半）

v0.8.6 把色块从 `<label><input type=color>` 换成 `<button>` 后，**所有「给这一行普通按钮做样式」的既有规则都会连带命中色块**：
1. `.ui-color-picker { padding: 0 }`（UA 默认 `1px 6px` 会把内层 span 挤成方块，父级 999px 圆角裁不掉）+ `.ui-color-picker span { border-radius: inherit }`（否则宽了露直角）。`--swatch` 声明在 span 上即可（span 铺满就显示，**不必上移到 button**）；
2. **更隐蔽的第二层**：`.ui-color-row > button { min-height: 30px; padding: 5px 9px }`（本意是给「默认」按钮）以特异性 `0,1,1` 盖掉 `.ui-color-picker { padding: 0 }` 的 `0,1,0`——第一轮修复「单元素测试看着绿、真机还是方块」。修法：选择器收窄为 `.ui-color-row > .menu-action-button`（ListMenu 与 ToolboxView 各一处）。

**方法论**：button 化新元素前，扫一遍容器里所有裸 `> button` 类型选择器；**改 CSS 特异性问题必须整页真实渲染量**（复刻测试测不出容器上下文规则）。

## 三、搜索正确性（两处）

### 1. 时间戳比较改 `Date.parse`

core 写入的时间戳**两种格式混存**：手写路径 `now_iso()` 给 `…Z`（UTC），日记导入 / `diary add --time` 走 `compose_timestamp()` 给 `…+08:00`（本地偏移）。字符串比较按**字面**定先后，跨格式必错位（实测：真实更晚的 `Z` 串排在真实更早的偏移串前面）。两处一起修：`searchScan.ts::stampOf`（返回 `Date.parse` 数值，脏数据退 0）与 `diary.ts::diaryByDate` 的天内排序（同口径）。**后果不只是排序错位——封顶取前 200 会截掉真正最新的**。`sort.ts` 的任务是纯 `now_iso` 路径，不受影响，没动。

### 2. 搜索中间批封顶

中间批 `onBatch(hits.slice(0, SEARCH_HIT_LIMIT), false)`——此前中间批把「已扫到的全部命中」原样进 store（宽词命中上万条时，每批驱动 VirtualStack 两个 O(命中数) 重算，16 批 ≈ 24 万次数组回调）。**封顶不影响最终结果**：最终批排序用的是局部完整 `hits`。

## 四、移动端时刻双轨

- `.time-col` 补 `overscroll-behavior: contain`：时间列滑到顶/底后滚动链冒泡到外层列表、被 pullrefresh 的 touchmove 接管——「滑动触发下拉同步，但时间滚轮不动」（真机原话）；
- `.time-picker` 从 `grid-template-columns: 1fr auto 1fr` 改**定宽** `calc(var(--font-control) * 6)`：flex 容器里 shrink-to-fit 会把两列摊成 44px（单列 17px）；
- **灰带（`.time-band`）不用动**：它挂在 `.time-picker` 里、相对 picker 定位（实测 band 宽 = picker 宽 − 左右 4px），轨道宽了自动对齐。别误判成「相对外层 228px 容器定位」而白修一通。

## 五、传输事件日志改异步

`transfer.rs::trace_event` 从同步 `std::fs` 改为后台任务：`tokio::runtime::Handle::try_current().ok() → handle.spawn(async { …tokio::fs… })`。依据：运行时 `worker_threads(2)`，同步写盘会卡住 accept / 心跳 / 其它传输（同文件里大文件读写走 `tokio::fs`/`spawn_blocking` 就是为同一件事立的纪律——新代码不能在同一处当反例）。`Handle::try_current` 兜底：runtime 外（个别单测直呼 emit）静默跳过，**不能 panic**（直接 `tokio::spawn` 会）。其余不变：只记非 progress 事件、2MB 上限、超限砍前一半按行边界切。

从前工具箱主界面与工具子页的头部图标写死 26，而「我的一天 / 日记 / 记账」写的是 34——两处各写各的。现在统一到一个常量：`styles.ts::PAGE_HEADER_ICON_SIZE = 34`（Workspace / DiaryView / LedgerView / ToolboxView 的主头部与子页头部都从它取），`.toolbox-header-icon` 的盒子也与 `.header-icon` 同口径（38×38）。

## 八、追加需求 B：工具箱与工具子页的三点菜单

### 1. 复用现有这套（用户的硬要求）

「新增的组件，如果是已有样式，要尽量复用现有样式，除非用户明确说明了特殊样式要调整。」工具箱这一版最初把菜单开在**鼠标位置**上、还给工具的取色状态各写一份——都是自己造轮子。现在：

- **菜单本体是 `ContextMenu` + `MenuItem` + `MenuSeparator`**（与「我的一天」的列表菜单同一套组件）；
- **定位复用点锚定约定**：`x = rect.right` / `y = rect.bottom + 6`、`xAlign="right"`、`anchor={按钮}`——菜单贴在三点按钮**正下方、右缘对齐按钮右缘**（`ContextMenu` 内部除缩放）。桌面与移动端都量了这个几何（回归脚本断言 rightGap/topGap ≤ 2px）；
- **同一个按钮再点一次 = 收起**（`openAppearanceMenu` 里比对 anchor，与记账/日记的齿轮同一条 toggle 语义）；
- **结构与普通页面逐字一致**：配置在上（relay 服务，只在传输工具页）→ 分割线 → `UI颜色` → `背景颜色`；
- **取色走统一取色盘 + 草稿预览**（`openColorPicker` / `colorPreview`），不是任何老逻辑。

### 2. 外观分两层（每个工具单独调）

- 工具箱主界面：`toolbox.accent` / `toolbox.backgroundColor`（原有）；
- **每个工具子页**：`toolbox.toolAccents` / `toolbox.toolBackgrounds`（新增，键必须是工具目录里的 id：`random/rmb/scratchpad/transfer`，core 侧按 `NAV_TOOL_IDS` 白名单校验——与 `appearance.navItems` 同一条纪律）；
- **进同步共享子集，三处清单一起改**（教训见 v0.8.3 的「预置标签只发不收」）：`is_shared_settings_path`（刷 LWW 戳）+ `settings_payload`（发）+ `apply_settings_record`（收）——只改第一处的症状是「本机改了、戳也刷了，别的设备永远收不到」，`sync/merge.rs` 里有往返用例钉住；
- **FieldMeta 的 kind 写 `object` 而不是 `map<…>`**（与 `appearance.dueColors` 同一条纪律）：前端「导入设置」按 kind 判断要不要摊叶子，带 `map<` 前缀会被逐键拆成 mapKey 写入，而这两个路径不收 `--map-key`，整份导入会静默失败；
- 取值两层回退（`styles.ts::toolboxAccent/toolboxBackground` 的 `toolId` 参数）：工具没配过 → 跟主界面 → 再空 → 应用默认。**工具子页没配过也跟主界面**，所以「一次调好全部」与「每个工具单独调」两种用法都成立；
- 「默认」按钮：主界面回应用默认；工具子页**删掉自己那一键**（回到跟主界面）；
- 预览作用域按路由分：主界面 `toolbox`、工具子页 `toolbox:<工具id>`（预览只染当前页）。

### 3. relay 服务（三选一）

配置项改成「**复用同步配置 / 使用默认服务 / 自定义服务**」：
- 语义与 core 的 `transfer.relay` 三态一一对应：空 = 复用同步的 `sync.p2pRelay`；`default` = n0 公共 relay（**新的出厂默认**，`model.rs::TransferSettings` 与 `defaults.ts` 同步改）；其它 = 自部署地址；
- **同步功能没开启时「复用同步配置」灰着不可点**（`disabled={!syncConfigured}`，判据 = 功能开关 + 有账户密码）；
- **默认勾选在「使用默认服务」**；
- 勾选图标**住在最左侧的定宽槽位**（`MenuItem` 的 `checkable`：槽位对每一项常驻、未选中只留空格）——勾在行尾时「选中项一换、最宽的那一项跟着换」，二级菜单宽度就会跳一下（用户明确要求「点击不同的不应该导致二级菜单宽度变化」）；`checkable` 同时挂给了排序方式 / 移动到分组 / 卡片类型 / 改账户 / 计划内分组（同类菜单一起稳）；
- 子菜单**定宽** `calc(var(--font-control) * 13)`：三个选项都是 5 个汉字、本该等宽，输入框用 `width: 100%` 撑满不参与「谁最宽」，于是任何选中状态下同宽；
- 输入框与提示行回到项目风格：字号继承菜单的 `--font-control`（原先自降 4px）、提示行与 `.menu-empty` 同一种静音小字（`0.88em`）；
- **提示只留「下次上线时生效」**（原先在线/离线两句：在线那句描述的「保存后自动重新上线」是内部行为，没必要占位）。
- `disabled`（只走直连）不在 GUI 提供了，但 core 与 CLI 仍然认这个值。

## 九、踩坑总表（方法论，比单条 bug 更值钱）

| # | 坑 | 一句话免疫法 |
|---|---|---|
| 1 | 视觉像素 vs 布局像素 | `getBoundingClientRect` 含缩放要 ÷uiScale；`scrollHeight`/`offsetWidth`/`clientWidth` 本就是布局像素，**不能再除** |
| 2 | 缩放壳里挂第三方指针交互组件 | 让它**视觉尺寸==布局尺寸**（反缩放层 + 宽度传视觉口径 + 宿主高度显式补） |
| 3 | CSS 特异性踩踏 | 只在**整页真实渲染**里暴露；单元素复刻测试测不出容器上下文规则 |
| 4 | 提交挂在 blur 上的控件 | **确认按钮自己的 mousedown 就是那个 blur**——确认路径必须先冲刷 pending 状态 |
| 5 | 配置键的作用域 | 编辑端写什么键，消费端必须读同一个键；聚合视图要双回退 |
| 6 | 测试断言的盲区 | 只数事件次数/只看最终值测不出几何与时序（把手指歪 44px、取消不还原照样全绿） |
| 7 | 自己造轮子 | 有现成组件/样式/调用约定就照抄；菜单的锚定是「x=rect.right / y=rect.bottom + 6 + xAlign=right + anchor」这四件套 |
| 8 | 「即输即生效」+ 防抖 | 停输才落盘，但菜单/弹层关闭必须 flush 一次，否则最后一笔静默丢 |

## 十、这一版做对的地方（值得照抄的）

- **先探测再定稿**：把手指脱靶、菜单贴边、二级菜单宽度都先在真实浏览器里量出来（`v087-fixes-test.mjs` 一开始就是探针），静态推演会被实测推翻。
- **修一处、扫一处**：删旧 `ColorDraftActions` 时把「谁还在引用」全查一遍（脚本里 4 处旧断言一并更新）；`MenuItem` 的勾选槽位一次性挂给 5 个同类菜单。
- **把用户的复用要求落成断言**：工具箱菜单的锚定几何 + 主界面/子页两层颜色互不干扰，都进了回归脚本——「复用」不再是口头承诺。

## 十一、未验证清单（点名到「哪一端、哪条路径、由谁手测」）

- **安卓真机**：色盘窄屏是否溢出、把手指在触屏上的跟手度（`touch-action: none` 只保证不滚页面）、工具子页 ⋯ 菜单的锚定位置、时刻双轨滑动不触发下拉同步、`EyeDropper` 不渲染时的操作行排版（少一枚按钮）。
- **Linux（WebKitGTK）**：`overscroll-behavior` 的支持度（老 WebKit 不认时行为回落到旧样）、色盘 `--ui-scale` 反缩放层在 WebKit 下的渲染、`EyeDropper` 不存在时按钮不渲染。
- **Windows 真机**：吸管按钮在 WebView2 里真能取到屏幕颜色（API 在场不等于权限/行为正确）、菜单翻上时 `maxHeight` 兜底的可视效果。
- 以上三端本版均**没有真机验证**，交给 CI 的只有编译与构建（`ci.yml` 双平台编译检查 / `release.yml` 三平台构建）。
