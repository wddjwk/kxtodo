# v0.8.3 版本档案（两个新能力 + 一批短需求 + 前两版 review 的甄别修复）

> **这份文件是什么**：v0.8.3 的完整改动档案。这一版有两个成体系的新能力——**「日期与提醒」**（面板 + 提醒运行时）与**「文件传输助手」**（iroh 打洞直传）——其余是工具箱/标签/临期高亮的短需求，外加对 v0.8.1–v0.8.2 的 11 条 review 逐条甄别后的修复。
> **什么时候读它**：改任务提醒（`reminders.rs` / 提醒台账 / 时钟跳变）/ 文件传输（`transfer.rs` / 传输 UI）/ 「日期与提醒」面板与它的三个入口 / 工具箱的固定与拖动 / markdown 行首空白与任务项映射 / 临期高亮四档配色之前；排查「提醒没响」「提醒响了两遍」「传输卡在等待对方」「缩进被吃掉」「点勾选框翻错行」「导入带设置就失败」这类症状之前。
> 当前生效的规则以主题文件为准（`frontend.md` / `invariants.md` / `ui-patterns.md` / `sync.md` / `cli.md` / `ledger.md`）；这份档案留的是「为什么这么设计、错的行为长什么样」。
> v0.8.2 见 `v0.8.2.md`，v0.8.1 见 `v0.8.1.md`。

## 一句话

两个新能力都刻意**复用已有的地基**而不是另起一套：提醒跑在调度线程现成的 500ms 节拍上（不新建 ScheduleEntry、不进 `tasks.json`），弹窗走前端既有的 `showNotification` 唯一出口；文件传输复用同步那一套 iroh/pkarr 打洞（换 ALPN 与 zone 前缀，绝不与同步的连接互抢），UI 照 LocalSend 分收发两栏、配对语义照 croc 用一句口令。短需求里最容易出事的是**跨语言的同口径常量**：临期高亮从三档变四档，一共要改四处（前端默认配色、前端 normalize、core 的校验、色盘 UI），漏掉任何一处都是「界面能选、存不进去」或「存进去了、刷新就没了」。

## 一、日期与提醒（需求 10 / 13）

### 面板：一个组件、三个入口

`TaskDateReminderPanel.svelte` 是唯一的实现，三处宿主只是把它挂进各自的浮层：右键菜单「日期与提醒」（`Workspace.svelte`）、卡片上点日期或时刻（`TaskCard.svelte` 的 `.task-date-popover`）、编辑器工具栏的日期按钮（`MarkdownEditorModal.svelte` 的 `.editor-meta-pop`）。**入口只负责挂载与写回**（`onSave` / `onClear` / `onClose`），面板内部的状态机（`main` / `time` / `custom`）与返回键层级完全自洽。

自上而下：日历 → 时刻行 → 提醒行 → 底部「清除 / 保存」。几条刻意的行为：

- **点日期不关面板**（需求 10.2）。它不是「选一个值就走」的一次性浮层，而是有多项配置的表单；只有清除/保存（或点外面）才关。
- 时刻行：`Clock` 图标 + 灰色占位「添加时间」，有值时显示时刻与一枚清除叉；点进去是**双轨滚轮**（时/分），默认停在当前时刻，底部「清除 / 确认」**都回上一级**（确认写值、清除抹值）。
- 提醒行：`Bell` 图标 + 灰色占位「添加提醒」，已有提醒是一串胶囊（悬浮出叉删除），末尾一个加号 → 五项菜单：一小时后 / 两小时后 / 截止前一小时 / 截止前五分钟 / 自定义。**「截止前」两项只在设了分钟时刻时可用**（没有时刻就没有可依附的截止点）。「自定义」是二级视图，顶上「日期 / 时间」两个标签页。
- 日历抽成了 `CalendarGrid.svelte`（日格 + 年月浮层 + `back()` / `reveal(date)`），`DatePicker.svelte` 与新面板共用一份——两处日历行为不一致是这一版之前就该收的账。

日记走的是**同一个日历、不同的面板语义**（需求 10.6）：右键菜单叫「修改日期」，只有日历、没有时刻行与提醒行（日记的时刻在 `createdAt` 里，不是提醒的依附对象），选完即把日记挪到那一天。

### 数据与运行时

- 模型：`Item.reminders: Vec<Reminder>`，`Reminder` 是 `#[serde(tag = "kind", rename_all = "camelCase", deny_unknown_fields)]` 的两档——`absolute { at }`（RFC3339 UTC 瞬时）与 `beforeDue { minutes }`（0 = 到点时）。**规则跟着任务同步，台账绝不进同步载荷**：一台设备响过不能让另一台永远不响。
- `reminders.rs`：`parse_rules` / `parse_rules_opt`（CLI 的 `due-60`、`+1h`、RFC3339 三种写法）、`due_in_zone`（把 `dueDate`+`dueTime` 按本地时区解成瞬时；**DST 歧义时刻直接拒**，不猜）、`resolve`（把 `beforeDue` 折算成瞬时）、`normalize_metadata`（日期/时刻/提醒是一个事务：新增的「截止前」没有时刻就拒、清掉时刻连带清掉「截止前」、去重按瞬时；已过去的**新增**规则拒 `REMINDER_IN_PAST`，未改动的旧规则允许留着）、`plan`、`clock_discontinuous`、`Engine::poll`。
- **发送台账**在 `runtime/reminders.json`：至多一次的凭据（`claimed` / `sent` / `skipped` / `failed` / `cancelled`）。它属于本机运行时，与同步水位、设备密钥同层。
- 跑在哪：`scheduler.rs::run` 的既有 500ms 循环里多调一次 `reminders.poll(core, now, reset)`。**首轮一律 `reset`**（刚启动看见的「已到点」全是停机期间错过的，不补发），之后每轮用 `clock_discontinuous`（墙上时钟与单调时钟**都看**，5 秒容差）判断休眠唤醒/改时间/换时区，跳变就 reset——「已过时的通知直接忽略」这条需求（10.7）就是这么落的，桌面与移动端同一份代码。
- 看门狗：`reminder_work: Arc<AtomicBool>` + `Scheduler::has_reminder_work()`，`host.rs::hidden_host_should_exit` 有未触发提醒时不退出（否则无窗口 + 无定时任务的常驻 Host 会在提醒响之前自己走掉）。`start_scheduler` 也改成幂等（`if slot.is_none()`）。
- 弹窗：桌面走 `show_notification_window`；**移动端 `MobileBackend::show_notification` 直接 `emit("kxtodo://notification")` 交回前端**——`stores.ts::showNotification` 已经是移动端通知的唯一出口（系统通知插件 + 权限申请 + 失败降级 Toast），Rust 侧再抄一遍就是两套口径。
- 移动端定时能力（10.7）：`ops_schedule.rs` 的 `ensure_platform_supported` / `ensure_action_supported` 收窄成「移动端只允许 `Action::Notification`、不允许 `Trigger::Condition`」，`caps.scheduler` 在移动端翻真（侧栏「定时任务」行随之出现）。**本版不做安卓保活**：进程不在就不响，这是明确的设计取舍。

## 二、文件传输助手（需求 11）

`crates/core/src/transfer.rs`（新）+ 壳的命令 + `src/lib/tools/TransferTool.svelte`。

- **配对**：一句口令（`CODE_MIN_CHARS = 8`，去首尾空白后按字符数算）。口令派生两样东西——pkarr 房间的 `SecretKey`（`sha256("kxtodo-transfer/v1/room/{code}")`，zone 就是公钥，所以「同一句口令 = 同一个房间」）与握手令牌（`sha256("kxtodo-transfer/v1/token/{code}")` 对**排序后的两个 EndpointId** 做 HMAC），用来在连上之后确认对面就是同一句口令的那台，而不是同房间里的第三者。
- **ALPN 是 `kxtodo-transfer/1`**，与同步的 `kxtodo-p2p/1` 必须不同：同一个 iroh 端点上 ALPN 是唯一的路由依据，重了就会被同步的 accept 循环抢走连接。relay 与 pkarr 目录沿用 p2p 同步那一套（`transfer.relay` 空 = 跟 `sync.p2pRelay` 同一个，再空 = n0 公共服务；`disabled` = 只直连/局域网），界面右上角可自选（需求 11 的「跟 p2p 同步一样」）。
- **协议**：4 字节大端长度前缀的 JSON 帧（`MAX_FRAME_BYTES = 8MB` 上限，防一个坏长度把内存吃光），清单 → 逐文件流 → 每个文件一个 `fileDone` 回执；文件夹 = 清单里多条 `rel` 路径，接收侧 `safe_join` 逐段校验（**任何一段跑出保存目录就拒**），进度条一文件一根。文件大小在 core 侧 stat（清单里的 size 只用于界面预显，进度条的「总」不能靠对方报）。
- **与账号体系完全无关**（需求明确要求）：不读同步凭据、不进 settings 的同步子集、不写审计。会话状态是内存里的 `Session`（`cancel(id)` 可以中止），进度经 `TransferSink`（`Arc<dyn Fn(Value)>`）事件式吐给前端。
- 移动端：发送侧走 webview 的 file input，字节按 base64 分片暂存到 `runtime/transfer-outbox`（scoped storage 下 core 只能这样拿到内容）；接收目录**两端同一份实现**——都用 `download_dir()` 下的 `kxtodo-transfer`（Android 的 `download_dir()` 就是 `getExternalFilesDir(DIRECTORY_DOWNLOADS)`，外部目录、不需要任何权限、USB 与文件管理器都看得到；`app_data_dir()` 在 Android 上是内部 `/data/data/<pkg>`，收到的文件用户根本找不到）。
- 已知边界：浏览器 dev 预览里选不到文件，「开始发送」恒禁用（回归里就是这么钉的）；本版没有做「同一句口令多方会话」与断点续传。

## 四、markdown 行首空白（需求 14）：为什么是「补硬换行到上一行」

用户写 `1. xx` 换行再敲一个 tab 写 `1.1 xx`，marked 把它当段落的 lazy continuation：换行折叠成空格、缩进整个丢掉，三行挤成一行且顶格。

`markdownIndent.ts::preserveLeadingIndent` 在进 marked **之前**把行首空白换成渲染得出来的东西：缩进换成**不间断空格**（普通空格在 HTML 里会被折叠），并给**上一行**行尾补一个 markdown 硬换行（两个空格）。

第一版是在本行前面插 `<br>`，实测被否掉：那一行因此不再是上一行的续行，marked 把列表**提前收口**，缩进行掉到列表外面另起一段（`<ol><li>xx</li></ol><p><br>…`），段首那个 `<br>` 还多顶出一行空白。补在上一行行尾则两全——`<li>xx<br>&nbsp;×4 1.1 xx</li>`，列表结构不动、行也分开了。

**不动的行**（marked 本来就理解，动了才是破坏）：围栏内、缩进代码块（≥4 空格且无 tab）、空行，以及缩进属于**结构**的行——列表标记（`- x` / `1. x`）、引用、标题、分隔线、setext 下划线。这条是实测出来的：`- item` 下面 tab 缩进的 `- sub` marked 会正确嵌套成子列表，一律转换会把用户写对的嵌套列表打成纯文本。`1.1 xx` 不算列表标记（`.` 后面不是空格），正是用户手写的大纲层级。

## 五、CLI 排查（需求 15）

- **`--initial -1500.00`**：v0.8.1 给 38 处文本参数补的 `allow_hyphen_values` 已经覆盖它（`cli_misc.rs::hyphen_leading_text_values_are_accepted` 里就有这条），本版只把 help 写清楚（等号与空格两种写法都认）。
- **`ledger categories` 平铺且乱序**：原来只按 `order` 排，子分类的 order 也从 1 起，于是「公交地铁」排在它父亲「交通」前面，Agent 必须自己按 `parentId` 聚合——而 help 写的是「列出两级分类」。改成**平铺但按树的先序**（大类后面紧跟它自己的子分类，同层按 order，先支出后收入），每项多带一个 `depth`（0/1）；help 与 Agent skill 同步说明。钉子：`cli_ledger.rs::categories_list_is_tree_ordered_with_depth`。
- **`ledger stats` 不带 `--side` 时两侧混排**：输出本来就带 `side` 字段、`percent` 本来就是**该侧内部**占比，问题纯粹是 help 没说 → 容易把收入占比与支出占比加成 200%。help 与 skill 都写明。
- **驼峰/下划线口径**：全量核对（走 clap 树 dump 出 125 个长选项 + 静态比对每个 `*Args` 的 serde 键与 core 的读取键）结论是**没有不一致**——CLI 长选项一律 kebab，core 的 params 与 JSON 输出一律 camel，转换靠每个 `*Args` 上的 `rename_all = "camelCase"`（唯一例外 `GlobalArgs`，它不进 params）。真正的风险是**漏写那一行 = 参数静默失效**，所以加了钉子 `cli_misc.rs::cli_long_options_are_all_kebab_case`，并把口径写进 `cli.md`。
- 顺手修的两处：`schema.rs::risk_for` 补 `sync.*` 分支（此前 `schema sync.pair` 报 read、与 help 的 write 顶牛，而 Agent 是照 schema 决定要不要先跟用户确认的）；`sync.historyRemove` 在 clap 树上没有自己的节点（CLI 是 `sync history --remove`），`command_schema` 加一层 `schema_node_path` 别名，否则这个动作的风险等级查不到。

### 顺带挖出来的（review 没提）

- **临期配色四档存不进去**：`ops_config.rs::expect_due_colors` 还写死「每项应为三个颜色」，而前端已经发四个 → GUI 改配色**必然失败**（正是需求 12 里用户报的那个弹窗的另一条成因）。三处一起改：core 的校验、`normalizeDueColors` 的档数（改成以 `DEFAULT_DUE_COLORS.length` 为准，不再写死 3）、`FieldMeta` 与 `model.rs` 的注释；CLI 回归补「三色的老写法现在要被拒」。
- **`transfer::send` 的错误码**：文件不存在时 `fs::metadata` 先失败 → 报笼统的 `IO_ERROR`，`TRANSFER_FILE_MISSING` 那一支成了死代码。按 `ErrorKind::NotFound` 分流，另加 `TRANSFER_NOT_A_FILE`（目录当文件传是调用方的 bug，但错误要说清楚）。

## 七、这一版的教训（写进主题文件的那些）

1. **跨语言的「同一个数字」要一次改齐，并且用 `include_str!` 钉住**。临期配色从三档变四档涉及四处（前端默认配色 / 前端 normalize / core 校验 / 色盘 UI），漏掉 core 那处的症状是「界面能选四个色、保存必失败」。`tests/frontend_contract.rs` 就是为此存在的：注释说「两边要一致」一定会漂。
2. **乐观更新必须自带回滚**，尤其是**不发域事件**的 `gui.*`：没有快照来纠正，失败就是界面与盘永久分叉。回滚要判「这期间是否又被改过」，用**对象身份**比就够（store 是不可变更新），不必深比较。
3. **`onMount` 的 cleanup 要把它注册的东西全释放**。只 `return addBackInterceptor(...)` 看着像配对好了，其实只释放了拦截器；同一个 `onMount` 里 `addEventListener` 的东西一个都没摘。
4. **单测可能钉住错误契约**（有序任务项那条）。写完测试问一句：这条断言的依据是「marked 实际怎么渲染」还是「我以为它怎么渲染」？前者要跑一遍验证，后者迟早害人。
5. **同类修复要做类级扫描**：`closeOverlays` 漏第三处、`return addBackInterceptor` 的两处、色盘「活值 vs 落盘」的四处，都是一处修好、别处照旧。
6. **纯逻辑模块要能跑 node 单测**（`markdownIndent.ts` / `markdownTasks.ts` / `dueHighlight.ts` / `sort.ts` / `reminders.ts` 都不 import marked/DOMPurify/stores）。这一版的缩进与任务项两处逻辑，全靠这条才能在十秒内对着 marked 的真实输出反复对齐。
7. **本地安卓交叉检查必须带上壳 crate**（打 tag 之后才发现，付了一版发不出去的代价）。`transfer_default_save_dir` 的移动端分支写了 `app.path().external_app_data_dir()`——Tauri v2 的 Android `PathResolver` **没有这个方法**，而本地 `cargo check --target aarch64-linux-android -p kxtodo-core -p kxtodo-server` 只覆盖两个纯 Rust crate，`src-tauri/src/lib.rs` 里 `#[cfg(not(desktop))]` 的分支一行都没编译过，`ci.yml` 的双平台检查也只编桌面目标 → 一路绿到 `release.yml` 的安卓栏才红。修法不是「再找一个移动端专有 API」，而是**把 cfg 分支整个去掉**：Android 的 `download_dir()` 本来就是 `getExternalFilesDir(DIRECTORY_DOWNLOADS)`（外部目录、免权限），两端同一份实现。命令与理由写进 `pitfalls-android.md`「构建环境与入口」。**写平台专有代码前先去看那一份 `PathResolver` 到底有哪些方法**（`~/.cargo/registry/src/*/tauri-*/src/path/android.rs`），别按桌面版的印象编。
