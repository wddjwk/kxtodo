## 一句话

这一版没有新功能，全是**把 v0.8.4 做坏的地方修回去**：三条 P0 里两条是「新增代码踩到了别人」（`.transfer` 撞记账转账行）与「复用地基时把共用资源关了」（发送会话关掉在线端点），一条是**单位混用**的累积误差（壳上有 `transform: scale()`，`getBoundingClientRect` 是缩放后的视觉像素、`scrollTop` 是布局像素）。追加的 33 号需求（渲染态勾选）则把一个「渲染为纯函数」的例外开得可控：**手术式 DOM 更新 + 文本匹配豁免 + 账本 adopt**，三件缺一不可。

## 一、P0：三条严重 bug

### 1. 裸类名 `.transfer` 踩踏记账转账行

`src/styles/toolbox.css` 里给传输页根容器写了 **无作用域的裸类名** `.transfer { display:flex; flex-direction:column; gap:14px; width:100%; max-width:720px; margin:0 auto }`，而记账转账行是 `<em class="ledger-entry-account transfer">`——**全球级联里所有转账条目**都被命中：竖排 + 撑高 + 占满小字行。改成 `.transfer-page`。

教训已写进 `invariants.md`（CSS 铁律）：**新增全局选择器一律带模块前缀，禁止裸名词类名**；新增/改全局 CSS 之后要拿「本版新增的选择器清单」逐个过一遍（`git diff <上版> -- src/styles` 里 grep 出 `.类名` 再比对 `src/` 里的用法）。当时做过同类扫描：全项目只有 `.transfer` 一条裸名词踩雷。

回归：`scripts/ledger-ux-test.mjs` 的转账行断言从「能渲染」升级成**布局断言**——`.ledger-entry-account.transfer` 的 computed `flex-direction === "row"` 且行高与普通行一致（≤4px 差）；`scripts/v085-fixes-test.mjs` 第 1 节同款。

### 2. 发送结束就关掉共享端点 → 每发完一次整个助手掉线

v0.8.4 把发送从「每次自起端点」改成**复用在线会话的共享端点**，但收尾 `finish()` 仍然无条件 `close_endpoint()`。iroh 的 `Endpoint::close()` **对任何一个 clone 调用都会关掉整个端点**（没有引用计数保活）→ `online_loop` 的 accept 返回 None → 报 `TRANSFER_CLOSED` → 前端收 error 离线。

修法（`transfer.rs`）：`Session` 新增 `connection: Mutex<Option<Connection>>`；
- **发送会话 `endpoint` 放 `None`**（共享端点由在线会话自己管），连接建立后存进 `connection`；
- 取消（`cancel()`）关的是**本会话的连接**（`connection.close(0, b"cancelled")`），它能从阻塞读写里把任务叫醒；
- 接收会话也持有自己的连接（同一个理由）；
- `finish()` 只丢弃连接句柄，**绝不 close 端点**（端点只有 `go_offline` 关）。

回归：`tests/transfer.rs::folder_transfer_roundtrip_with_progress` 末尾新增两条断言——发完一次后 `status(sender)["online"] === true`，且**反向（接收方 → 发送方）还能再传一条**。原来的测试只断言「传完了」，这就是它全绿的原因。

### 3. VirtualStack：跨 `fullBelow` 阈值后高度记账永久失效（外加真根因）

两层问题：

1. `track` action 在创建时按当时的 `fullMode` 固化成 no-op，keyed each 复用的行 action 不会重建 → 99 → 101 条之后那批行永远停在估高上。
2. **真根因（写测试时才挖出来）**：`measure()` 用 `node.getBoundingClientRect().height` —— 壳上 `transform: scale(uiScale)`（默认 0.75）让 rect 返回**缩放后的视觉像素**，而 `scrollTop` / 占位高度都是**布局像素**。两套单位混用 → 每行欠 25%，行越靠后累积误差越大，「日历点某天跳列表」会差出好几张卡。

修法（`VirtualStack.svelte` + `shared.css`）：
- `measure()` 改用 **`offsetHeight`**（布局像素，与 `scrollTop` 同一坐标系）；整数取整由 0.5px 阈值吸收；
- **两种模式都记账**（全量模式的项数有 `fullBelow` 上限，量高很便宜；不量的话跨阈值切窗口化时占位全是估值）；
- **`.virtual-item { display: flow-root }`**：默认块盒会把子卡片的外边距（`.diary-card` / `.task-card` 的 `margin-bottom`）折叠到 wrapper 之外，wrapper 量出来比实际占位小；
- `scrollToIndex()` 落位后**双 rAF 再对一次位**（第一次用的是估高前缀和，窗口挂上并对齐附近行之后前缀和才准）。这里**不设「用户滚过就放弃」的守卫**：内容高度被量准后浏览器会顺手把越界的 `scrollTop` 夹回来，那不是用户操作。

回归：`v085-fixes-test.mjs` 第 3 节（100 条全量 → 界面上加两条跨阈值 → 断言总高 ≈ 102 × 实测中位高）与第 9 节（日历跳天）。

### 4. 在线会话的生命周期（定案）与状态提升

三条规则：① 有活跃传输任务，退出工具页 / 应用退到后台都不断连接；② 已配对但没有任务，退出工具页保持在线，**手动点「离线」才下线**；③ 未配对，退出工具页即清理界面状态。

实现：新增 **`src/lib/transferStore.ts`**（模块级单例），工具页退化成它的视图：

- 状态全在 store：`tab / online / selfId / code / saveDir / devices / selectedDevice / sessions / texts / requests / picked / historyEntries / deviceHistory / busy`；
- **事件订阅也在模块级**（`ensureTransferRuntime()`，`App.svelte` onMount 调一次）：订阅 `kxtodo://transfer` 后**先问一次 `transfer_status` 对账**（窗口重开/刷新后界面与 core 一致），并**恢复记住的口令自动上线**（工具页没开也收得到拨入）；`document.visibilitychange` 也在那里——页面隐藏时浏览器会强制释放 wake lock，回前台还有活跃会话就重新申请；
- remove：`leaveTransferPage()`（组件 onDestroy）——`online || 有活跃会话` 就什么都不清；否则清 sessions/texts/requests/picked 并清空 outbox 暂存；
- **手动「离线」清掉记住的口令**（`transferSaveCode("")`），免得重启应用又自己上线；换保存位置 / 改 relay 走内部的 `disconnect()` + `goOnline()`（**不清口令**）；
- 全局出口：人不在工具页时收到 `request` 就发系统通知（「X 想发送 N 个文件…打开工具箱 → 文件传输助手确认」），并给**侧栏「工具箱」行挂待确认角标**（`requests.length`）。当前通知栈（`showNotification` / tauri-plugin-notification）没有点击回调，所以「点击跳转」以「系统通知 + 角标」落位，不假装有点击穿透；
- **「自动接收」开着时不再挂确认卡**：core 那边没有待确认请求，挂出来按钮也是死的（v0.8.4 的隐藏 bug），只提示一句。

### 11/29. 拖动两件套

- **图标（含双列）模式落点**：`navDropIndex` 改成两步——先按 `clientY` 找所在竖带，再在带内按 `clientX` 与各行中心距离取最近项，左/右决定插前/插后；指针在行间缝隙或整块之外按最近一行的中心判前后。早前只比 Y，图标模式所有行共用一个竖带 → 永远命中第一行 → 拖谁都只能落到前两位。
- **分组树拖动实时让位**：`nodes.ts::planTreeMove` / `planTreeRootEnd`（**预览与提交共用同一份 planner**）→ `ListTree` 拖动中把结果顺序报给 `Sidebar`（`treePreview` 作为 `nodes` 传入）→ 行跟着指针让位、整棵子树随 `animate:flip` 平移；落点类（`.drop-before/.drop-after/.drop-inside` + 根末尾线）搬到 **`src/lib/listTreeDrag.ts` 的共享 store**——`ListTree` 是递归组件，每层一个实例，拖动逻辑住在按下指针的那一层，而目标行常属于另一层，状态留在实例里时**跨层拖动的虚框永远画不出来**（v0.8.4 的隐性缺陷：功能对、反馈丢）。

  两个必须知道的细节：`animate:` 指令所在元素必须是 keyed each 的**唯一子元素**（行 + 子树是并列两块，所以包一层 `.tree-item`，`display:flex; column; gap:2px` 保持行距）；指针落在被拖行自己身上时**保持现落点**（否则「拖到自己 → 清空 → 弹回 → 又命中」来回抖）。

## 三、P2/P3：协议卫生与收尾

- **12 接收确认卡多槽**：`Online.pending` 改 `HashMap<String, PendingRequest>`（按 `request_id`），`decide` 按 id 应答；UI 侧 `state.requests` 是数组、逐张渲染。单槽时第二张拨入会顶掉第一张，第一张的等待循环干等到 60 秒超时。
- **13 设备名缓存**：`online_loop` 按 device-id 缓存名字（`NAME_CACHE_TTL = 20s`），不再每 2 秒对每台设备各查一次公网 pkarr。
- **14 send fallback 不再 parse z32**：在房间条目里按 `entry.id.to_z32() == target` 比对（iroh 的 `FromStr` 只认 RFC4648 base32/hex），并给 fallback 补上**与设备列表同一个 fresh 过滤**（45 秒）——「列表里看不见的设备，发送也如实说不在线」。`parse_endpoint_id` 整个删掉。
- **15 大文件写盘不再卡运行时**：接收侧 `tokio::fs` + `BufWriter::with_capacity(CHUNK)`、发送侧 `tokio::fs::File`（运行时常驻 2 个 worker 线程，同步 IO 会把 accept/心跳全卡住）。
- **16 草稿纸水合竞态**：seed 前看 `dirty`（有未 flush 的输入就**跳过覆盖**，用户刚打的字优先）；`onMount` 里也只在 `!seeded` 时才读 localStorage。
- **17 历史文件加锁**：`record_history` / `clear_history` 走进程内 `Mutex`（读-改-写并发会吞条目）。
- **18 同名耗尽报错**：`unique_target` 找不到可用名返回 `TRANSFER_NAME_EXHAUSTED` 而不是回退覆盖（单测钉住）。
- **19–27 收尾**：删掉 `virtua` 依赖（评估过没用上）；`send_loop` 去掉没用的 `net_config`；`saveDueColors` 只写变更档、保存后草稿保留（与主题色/背景色三条路径统一）；`v084` 的编号断言补真四级嵌套、颜色断言改成「与正文同色」的 computed 比较；counters 深处编号与大字号日期面板跑了视觉回归——**权威口径是套件里的几何断言**（`v085-fixes-test.mjs` 第 24 节：深层编号的 li 与列表左边界都在卡片内、列表区无横向溢出；第 27 节：格宽 ≥ 字号 ×1.4、7 列定宽不溢出），截图（`test-data/v085-*.png`）只是**本地人工辅助**、不入库（`.gitignore` 里 `test-data/*.png`）；v0.8.6 需求 9 把这条口径写实；`blockCache` 更名 **`docCache`** 并修正注释（它从来不是块级，真·块级缓存留档备查）。

## 四、追加需求 33：渲染态勾选不再整篇重渲

【症状】>1000 字的长文档点渲染态勾选框，页面闪一次；再点不闪，过一会儿又闪——闪的是两阶段渲染的「快速版 → 完整版」装饰差（长文档必走两阶段，整篇重渲时新文本缓存必 miss）。

【修法】手术式更新，四步（`markdown.ts` + `markdownTasks.ts` + 两张卡片 + `deferredMarkdown.ts`）：

1. `markCheckedItem(li)` / `unmarkCheckedItem(li)` 从渲染管线里抽出来（渲染与点击**共用同一份**，等价性由构造保证）。勾选是结构性的：紧列表要建/拆 `span.md-task-label`（「删除线只划当前行」的载体），松散列表给它第一个 `<p>` 打类；拆包按原序搬回、对未勾选项幂等。
2. 点击时：**目标态以源码为准**（`markdownTaskChecked(next, index)`）→ `setRenderedTaskBox(box, checked)` 收敛勾选框与标记。**两个坑**：
   - 原生点击在事件派发前已经翻过 `checked`，拿 DOM 取反会翻回去；
   - **不能 `preventDefault`**——取消激活行为会让浏览器把 `checked` 还原回点击前的值（勾选框的原生翻转就是即时反馈）。
3. 卡片重渲入口一行豁免：`if (expanded && markdown === skipNextRender) { skipNextRender = ""; return; }`。**必须是文本匹配**：写失败回滚、远端同步、编辑器改写都对不上 → 落回正常重渲。
4. 豁免只认勾选：展开、编辑、设置变化的重渲路径一字未动。

**实施时挖出来的第三件（缺了它回滚会分叉）**：`deferredMarkdown` 的 `applied/appliedFull` 是「这份文本已经渲过」的账本——手术更新跳过了整篇重渲，账本必须跟上（`fullRender.adopt(next, nodeId)`），否则文本**回退到更早的那一份**时（写失败回滚 / 远端同步），`schedule` 会认为「已经渲过」而跳过，界面永久停在手术后的状态。另外 `{@html}` **只与上一次的值比**，同值不重建——回退时命中的是 `docCache` 里的旧 HTML（与当前值相同），所以卡片的写入回调要**先清空再写回**强制重建一次（两次都在同一个任务里，浏览器不会在中间绘制）。

【验证】单测 `src/lib/__tests__/taskToggle.spec.ts`（happy-dom）：手术翻转后的活 DOM 与「改源整篇重渲」的 DOM 形态逐字节一致——勾上/勾掉 × 紧/松列表 × 嵌套子项，外加 unmark 幂等与重复 mark 幂等；Playwright（并入 `v084-fixes-test.mjs` 第 33 节）：点击后 `checked` 已翻、`li.md-task-done` 已打、**代码块高亮节点身份未变**、`renderStats.fast` 不增长；再点一次同样不重渲；编辑器把正文写回原文（模拟回滚后的那次源变更）→ 重渲纠正、勾选框回原态。perf-bench 13/13 不变。

【同类场景（知会，不扩大施工）】搜索结果里的卡片与搜索外是同一套组件（自动覆盖）；编辑器「预览」里的勾选与展开卡片上改日期/提醒属同机制远亲，低频交互，接受现状——修它们才是过度设计。

## 五、这一版做对的地方（改动时不要误伤）

- **`transferStore` 的分层**：工具页只画与转发，core 的 `transfer_status` 才是权威；`ensureTransferRuntime` 幂等、浏览器预览（非 Tauri）整体空转。
- **`planTreeMove` 预览与提交同源**：任何「让位效果」与「落盘结果」不一致的 bug 都从这里杜绝。
- **`adopt` + 文本匹配 + 手术更新**三件套：单看任何一件都不完整（跳过重渲 → 账本过期 → 回退分叉）。
- **测试的两条新纪律**：`v085-fixes-test.mjs` 的 `dragBy()` 逐段拖动（真实指针是连续采样的，Playwright 一次 `steps` 走完时 flip 动画中途的矩形不代表产品行为）；量尺寸一律 `offsetWidth/offsetHeight`（壳上有缩放，`getBoundingClientRect` 是视觉像素）。
- 老套件里对已消失 UI 的断言（`.ledger-gear-panel` / `.transfer` / 齿轮面板里的「搜索记账」/ 预设色块的「保存」）随本版一并更新——**断言跟着当前实现走**，但要在版本档案里留一笔（就是这里）。
