# v0.8.6 版本档案（极限数据量下的搜索/树/移动端补课 + 传输全链路整治 + 取色盘统一）

> **这份文件是什么**：v0.8.6 的完整档案。主题是**在极限数据量下把三处体验补回来**（全局搜索、分组树、移动端整页切换）、**把文件传输助手从选文件到接收取消逐环过一遍**（含两条双 P0 主链路 bug）、**取色盘统一成一个组件**（内嵌 iro + RGB/HEX + 取消/确认）。
> **什么时候读它**：改全局搜索 / 改分组树拖动 / 改移动端整页视图 / 改浮层定位 / 改文件传输（路径语义、拒绝语义、设备名）/ 改取色之前；排查「搜一次卡死」「拖动一跳一跳」「从记账返回主界面闪一下」「桌面选文件发送必失败」「拒绝后凭空出现一张失败卡」这类症状之前。
> 当前生效的规则以主题文件为准（`frontend.md` / `invariants.md` / `ui-patterns.md` / `sync.md`）；这份档案留的是「为什么这么设计、错的行为长什么样」。
> v0.8.5 见 `v0.8.5.md`。

## 一句话

三件大事：**搜索从同步 derived 改成「预折叠索引 + 分块扫描 + 200 条封顶」**（15MB 文本不再一帧算完）、**拖动落点从「实时矩形」改成「布局位置 + 迟滞带 + 布局在动时不改判」**（原来 hover 振荡、整棵树反复 flip）、**传输清单的 `rel` 从绝对路径归一成相对路径**（桌面「选文件发送」在 Windows 上从来没成功过）。另有一件结构性收口：**12 处原生 `<input type="color">` 全部换成同一个 `ColorPickerPanel`**（Chromium 的原生色盘是系统小窗，DOM 不可定制）。

## 一、搜索：从「一帧算完」到「分块扫描 + 索引缓存」

### 1. 预折叠索引（按对象身份缓存）

`filterDiaries` / `filterLedgerEntries` / `buildVisibleTasks` 每敲一个键都要对全文 `toLowerCase()` 再 `includes`。现在各自有一份**折叠串**：

- 日记：`diaryFold(entry)` = 标题 + 正文 + 标签 lowercased，`WeakMap<DiaryEntry, string>` 缓存（日记是逐条不可变更新，改一条只新一个对象 ✓）。
- 任务：`taskFold(task)` 只折叠正文——**归属条目的名字刻意不进这条串**（改名只动 `state.nodes`、任务对象身份不变，缓进来就永久过期），名字命中改走 `matchingNodeIds(state, needle)`。
- 记账：`ledgerFold(book, entry)` = `{ text, amounts }` 两段，**外层按 `book` 身份索引**（分类名住在 book 里，只有整本换新才需要重算）。金额串与文字串**分开**是刻意的：金额带千分位逗号，混进文字串后「搜一个逗号」会把所有四位数的账都列出来（`amountNeedle` 那道门就是干这个的）。

### 2. 扫描器（`searchScan.ts`）：分块 + 封顶 + 可取消

`searchHits` 从 derived 降级为**可写 store + 扫描控制器**——derived 的求值是同步的，一万条流水 + 五千篇日记会在一帧里钉死界面。

- 每批 `SEARCH_CHUNK = 1000` 条，跑在 `requestIdleCallback(timeout: 120)`（旧 WebKit 没有的话回落 `setTimeout`）；
- 中间批**不排序**（渐进上屏），最后一批才按 `updatedAt` 全局排序并截到 `SEARCH_HIT_LIMIT = 200`。每批都排一遍的代价是 O(命中数²/批大小)，宽词命中上万条时不可接受；
- 防抖词一变就 `cancel()`（token 作废上一轮）；**清空同步生效**（不走 idle，直接清 store）；
- 搜索期间数据变了（同步回来、勾掉一条）要重扫：按 `[tasks, nodes, diaries, entries, categories]` 的**数组身份签名**比对，没变就一个字节都不重扫（`appState` 每次 UI 操作都换身份，不加这道门会白扫）。

### 3. 渲染：两处结果都接 VirtualStack + 「搜索中…」

`Workspace` 的搜索分支与移动端的 `SearchResults` 都改走 `VirtualStack`（命中封顶 200，只有视口附近在树上）。标题后跟一枚「搜索中…」（扫描未完结时），移动端结果面板空态同理。

实测（`perf-bench.mjs`，1000 任务 / 5000 日记 / 10000 账目）：宽词「基」命中 200 条封顶、**313ms** 上屏、扫描期 0 个 >100ms 长任务。

### 4. 卡片级 window 监听收敛

`TaskCard` 早先每张卡自带一份 `<svelte:window on:click on:pointerdown>`（几千张卡 = 万级监听器）。现在这两件事都是**全局唯一**的，收进 `cardOverlays.ts` 的一份 document 监听：

- 「日期与提醒」浮层**全局单例**（`datePopoverTaskId`）：一张卡开着、点别处一律不保存关闭、点另一张卡的日期自然「先关旧再开新」；
- 触屏「露出删除叉」（`revealedTag` / `revealedEmoji`）同款；
- 一份 `document` capture pointerdown 管两件事，面板与唤起按钮豁免（`[data-date-popover]` / `[data-date-anchor]`）。

## 二、分组树：展开动画 + 拖动落点全面重做

### 1. 展开/折叠改高度动画（`grid-template-rows: 0fr → 1fr`）

早先 `{#if !collapsed}` 直接挂子树：新内容**瞬间占满高度**，兄弟行再慢慢 flip 下去 → 视觉上「先盖住、再挪走」。现在子树容器常驻、收起态被裁到 0 高（不占位、不可命中），展开走 grid 轨道高度动画，**与兄弟行的 `animate:flip`（150ms ease）同频**。

代价与配套：**收起态的行仍然挂载**——落点判定必须把它们排除（`element.closest(".tree-children:not(.open)")`），否则会和后面的行重叠、命中看不见的行。

### 2. 拖动落点：布局位置 + 迟滞带 + 「布局在动时不改判」

三件都在 `dragHit.ts`（纯函数、有单测）：

1. **不用动画中途的矩形**。行让位走 `animate:flip`，而 flip 是**纯 transform**：`getBoundingClientRect` 拿到的是「飞在半路」的临时值，几行互相不自洽 → hover 振荡。布局位置（行最终会停在哪）才是稳定口径：`settledTop()` 把 rect 里的 `translateY` 减掉（壳上还有 `transform: scale(uiScale)`，元素自己的 translate 是逻辑像素、要乘缩放比）。
2. **边界带迟滞**（施密特触发器）：越过边界 `band/2 = 4px` 才换、回带内不换。行内 `before/inside/after` 三段判定同理。
3. **缝隙按中点判给邻近行**（`contiguousZones`）：行与行之间有 2px 间距，严格按 span 判定时指针走到缝里返回 null → 被当成「空白区」→ 落点被清掉/变成「拖到末尾」，整棵树乱跳。
4. **行动了、指针没动 = 布局在动**（`keepsPreviousDecision`）：这是实测抓到的抖动根因——拖条目到分组头中部判成「移入」→ 预览把条目挂到分组下面 → **分组头那一行整体上移 13px**，指针没动却已落到新几何的下缘之外 → 下一帧翻成「插到后面」→ 再让位、再翻回来。现在只要「行的几何变了而指针位移 ≤ band/2」就保持现判；指针自己动了照常重算（所以「在行内往下挪一点改判」仍然可用，慢慢挪也不会被卡死）。

固定区（`.nav-row`）的落点判定同步改成同一套：settledTop + 中线迟滞 + rAF 合并预览。

调试手法（值得复用）：把每帧判定写进页内数组（`window.__treeHover`），失败时一次性读出来——**不要在拖动路径里插 `page.evaluate` 探针**，那会把时序抖动的 flake 掩盖掉（本版实测：加了探针就全绿，去掉就跑出失败）。

### 3. 拖动库评估结论

`svelte-dnd-action` 0.9.79 的 peer 支持 Svelte 5，但对本项目的两条纪律直接冲突：它自管预览排序（`planTreeMove`「预览与落盘同一份 planner」保不住），而树形嵌套还得自己维护跨 zone 语义。**结论：不引入，走自研**（规格就是上面那四条），与 v0.8.4 否掉 virtua 的判据同源（依赖必须先满足现有纪律，而不是反过来）。

## 三、移动端整页视图：不透明覆盖而不是 `display:none`

`.view-ledger` / `.view-diary` / `.view-toolbox` 三组原本把 `.sidebar` 与 `.workspace` `display:none`，返回主界面时整块重排+重绘（闪）。

现在这三个整页层（本就 `position:absolute; inset:0`）改成**不透明覆盖**，底下两栏常驻：

- CSS 改 `visibility: hidden`（保留布局、不重排、不可聚焦、摘出可访问性树）；
- 组件给两栏加 `inert`（`coveredByFullPage`）——旧 WebKit（Linux 桌面 / 老 safari13 target）不认 `inert` 时由上面那条 CSS 兜底；两条都会挡住 Tab 聚焦（有回归断言）。
- `.view-list` / `.view-content` / `.view-settings` 三组**保持 `display:none` 不动**（它们不是整页覆盖层）。

## 四、浮层定位标准化

`popover.ts` 新增 `placePopover`（点锚定的浮层定位，**逻辑像素进、逻辑像素出**），ContextMenu、日期浮层共用：

- **优先向下展开**（盖住唤起按钮会让「点按钮」变「点菜单」）；
- 下方连最小高度（120px）都放不下、或上方明显更宽松 → 翻到锚点上方且**下边缘与锚点对齐**；
- **四边一律钳制**：宁可限高内部滚动也绝不溢出（旧实现第三分支 `max(5, 120)` 会让菜单从视口底探出去）。

配套修的两处：

- **日期浮层量尺寸要等双 rAF**：首帧日历格子还没定宽（`.date-picker-grid` 定宽 228 是 v0.8.4 钉住的），量早了宽度偏小、钳制算错（实测面板从视口右边探出 20px）。落位前先 `visibility: hidden`，落好再 `placed`。
- **`MenuItem::adjustSubmenu` 补左缘钳制**：翻转只解决「右缘放不下」，窄视口下翻到左侧仍可能越左缘，用 margin 补回来（限高菜单里子菜单是静态定位，跳过）。

## 五、文件传输助手全链路整治

### 5.1【P0】`rel` 语义错误：绝对路径进了协议

两条病根：

1. **安卓选文件发送报「找不到文件」**：前端用 `` `${root}\\${rel}` `` 反斜杠拼暂存路径——Android/Linux 上 `PathBuf` 把整串当单个文件名；
2. **桌面「选文件/拖放」发送必然失败**：`rel` 是绝对路径（`transferStatFiles` 原样回传、`startSend` 恒传 `root: null`），接收端 `safe_join` 对含 `:` 的段直接 `TRANSFER_PATH_UNSAFE`（Windows）；Linux 不报错但会把绝对路径**镜像成一棵目录树**。

修法：新增 `transferManifest.ts`（纯逻辑 + 单测）——`filePick()` / `spoolPick()` / `folderPick()` / `textPick()` 四个构造器保证 **`rel` 恒为相对路径**、`root` 是那一层基准目录；`startSend` 按 `root` **分组拆成多次 `transferSend`**（跨目录多选、桌面文件 + 剪贴板图片混选都能发，顺带解决「混合清单静默丢文件夹」）。core 侧加**发送前 tripwire**：`root=None` 且 `rel` 形如绝对路径 → 连接之前报 `TRANSFER_MANIFEST_ABSOLUTE_PATH`（fail-fast）；`safe_join` 的 `:` 判定保留作纵深防御。

回归：`tests/transfer.rs` 三条（tripwire 的三种绝对路径形态 / 桌面选单文件落地在保存目录根且**没有镜像目录树** / 越界路径仍被拒）。

### 5.2 设备名：兜底 + republish 死代码

- 自动恢复上线时 `appSettings` 可能还没水合 → 名字为空 → `publish_name` 跳过空名字 → 对端只显示「未命名的设备」。core `go_online` 现在**名字为空时用 `KXToDo·{平台}` 兜底**并照常发布；前端**水合完成后补发 `transferSetName`**。
- `Online.name` 早先一个槽既当「当前名」又当「已发布名」，`current != published` 恒假 → 改名后的 republish 分支是死代码。拆出 `published_name` 槽修活。

回归：`renamed_device_republishes_its_name`（用一个**新来的观察者**验证——它没有名字缓存，看到的就是房间里真正发布着的名字）+ `empty_device_name_falls_back_to_default`。

### 5.3 / 5.4 拒绝语义与接收链路

- **拒绝不是错误**：core 拒绝时历史记 `rejected`（不是 `cancelled`）、发一条**信息性 `rejected` 事件**、**不发 error**——早先返回 Err（`TRANSFER_REJECTED`）让界面在一个从没建过卡的会话上**凭空画出一张「接收失败」**。发送侧收到 reject 帧的历史也记 `rejected`（与 `failed` 分开）。
- **等对方把 reject 读走再收尾**：连接句柄一 drop 就是 CONNECTION_CLOSE，抢在对方读到之前断线的话发送方只能报「连接断了」，所以拒绝路径 `timeout(2s, connection.closed())`。
- **错误文案不再吞真实原因**：只有 `TRANSFER_CONNECTION_LOST`（core 新错误码，用在帧读写失败上）才是「对方离线了（原因）」；本地错误（路径越界 / 同名耗尽 / 写盘失败）原样透出。这条规则抽成纯函数 `transferErrorText` 并有单测（判据是「被用户实测打出来的：接收失败却显示对方离线」）。
- **移动端「打开」**：用 `done` 的 `dir` + `fileDone` 的 `savedAs` 拼绝对路径存进会话（`joinPath` 纯函数），移动端会话卡打开**最后接收的那个文件**（目录 reveal 在安卓基本不可用）；「打开文件夹」仅桌面显示。
- **失败卡显示「已接收 N/M 个文件」**，锁屏边界写进工具页提示文案。
- 诊断出口：core 的 `emit` 现在往 `runtime/transfer-events.log` 追一行 JSON（**跳过 progress**——每 256KB 一条既没信息量又会阻塞只有 2 个 worker 的运行时），单文件 2MB 上限、超了砍前一半。

回归：`rejected_request_records_rejected_without_error_event`（本端 sink **不许**出现 `TRANSFER_REJECTED` 的 error、两边历史都是 `rejected`、发送侧仍在线且确实知道被拒了）。

### 5.5 界面杂项

口令输入框去密码框样式与眼睛按钮（普通文本 + `autocomplete=off`）；存储路径**中间省略**（头段可截断 + 尾段保留，`splitPathTail` 纯函数）；「更改 / 打开文件夹」另起一行；空态文案「输入相同口令以匹配」+ 卡片加宽；「离线」改「**下线**」并用新增的 `.menu-action-button.danger` 变体。

## 六、取色盘统一（内嵌 iro）

12 处原生 `<input type="color">`（`ListMenu` ×4 / `ToolboxView` ×2 / `SettingsDrawer` ×2 / `AccountManager` ×2 / `TagColorPicker` ×1 / `CategoryManager` ×1）全部换成 `ColorPickerPanel.svelte` + `colorPickerPanel.ts` 的**全局单例请求**：

- iro 色盘（`iro.ui.Box` + hue slider）用 `await import("@jaames/iro")` **懒加载**（构建产物里是独立 chunk，不进首屏链）；容器 `touch-action: none`（否则安卓拖动选色会顺手滚页面）；
- **RGB / HEX 双向联动**：`color:change`（任何变化，含程序写入）→ 同步输入框；`input:change`（只有用户操作）→ 推预览；
- **拖动预览按 rAF 合帧**：不合并的话一次拖动就是上百次 store 写入（`window.__kxtodoColorPick` 暴露 `previewEvents/previewWrites` 供回归断言「事件数 ≫ 写入次数」）；
- 语义与 v0.8.4 的草稿纪律一致：拖动/输入**只改草稿 + 实时预览**，「确认」才落盘，「取消」/点浮层外/Esc = 丢弃草稿、预览回退；键盘可达性**只补了 Esc**（如实留档，没做方向键调值）。

三个实现坑（都踩过）：

1. **不能在响应式块里用 `picker` 是否为真当「要不要挂载」的判据**——动态 import 在途时它还是 null，重跑就再挂一次，而每次 `await tick()` 都是微任务、永远不给 fetch 让路，整页主线程被这个循环饿死（实测：点一下色块页面直接卡死）。用 `activeKey` 记账。
2. **面板挂在 App 层（菜单之外）必须自己 `stopPropagation`**：不拦的话点一下色盘就冒到 `.app-shell` 的 `closeOverlays`，把菜单关掉（草稿一起作废）。
3. **Esc 要注册在 `window` 捕获**：菜单的 Escape 处理器也在 window 捕获并会 `stopPropagation`，同级节点之间 stopPropagation 管不住（两个都会跑），而挂在 `document` 上会被它拦住（实测 Esc 收不掉面板）。

## 七、小修

- **工具页标题统一**：四个工具页都是「左 = 返回箭头 + 图标 + 工具名，右 = ⋯ 菜单」，字号写死 `var(--font-title)`（= uiFontSize + 18，与 Workspace `h1` 同口径）；两个工具内部的标题行（`.toolbox-sub-title`）整块删掉。返回箭头**不能复用 `MobileBack`**（它按 `features.mobileBack` 在桌面隐藏，会把需求做反）。工具箱**主界面**的返回仍按系统设置走。
- **统计「自定义」日历的年月面板**：`mp-cell` 加 `white-space: nowrap`、浮层宽度按字号自适应（`max(240px, calc(var(--font-control) * 13))`）；内联进日历时宽度与日历同宽（228）。**日网格仍是 228 定宽**（几何断言「格宽 ≥ 字号 ×1.4」在大字号下依然成立，不需要改）——这条是需求 9 要的「适配结论」。
- **记账/日记齿轮 toggle**：已开着再点 = 关闭；并把 `anchor` 传给 `ListMenu`→`ContextMenu`（不传的话 capture 阶段 pointerdown 先关、click 再开，看着就是「点一下闪一下、关不掉」）。
- **relay 服务改成一级菜单项 + 二级钻取**（`MenuItem` 的 `submenu` 插槽），移动端自动钻入、桌面自动贴边翻转，零新机制。

## 九、这一版做对的地方（改动时不要误伤）

- **搜索的「渐进上屏 + 最后一批才排序封顶」**：中间批不排序是刻意的，别「顺手」给每批都排一遍。
- **折叠串按对象身份缓存**：任务折叠串里**不许**加入条目名（改名不动任务对象，缓存会永久过期）。
- **`contiguousZones` + `keepsPreviousDecision` 是两条独立的护栏**：前者治「缝里掉进空白区」，后者治「布局在动被当成用户在动」。删任一条都会退回抖动。
- **拖动判定的「保持现落点」有两个入口**：指针在被拖的行上、以及「行动了指针没动」。它们是 v0.8.5 与 v0.8.6 两次实测各补一条，别合并简化。
- **`transferManifest` 的四个构造器是 `rel` 语义的唯一出口**：任何新的取文件入口都要走它们（core 的 tripwire 只是兜底，不是主路径）。
- **`cardOverlays` 的一份 document 监听**：新加「点别处关闭」的卡片级浮层要挂进它，别退回每卡一份 `svelte:window`。
- **`placePopover` 是点锚定浮层的唯一几何**：新浮层不要再手算钳制。
