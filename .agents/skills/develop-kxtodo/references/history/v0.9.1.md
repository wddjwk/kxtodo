> 新能力两个：**日程分类（自定义颜色）**与**重复日程**；其余都是把 v0.9.0 的实现

## 一、P0：一个坏掉的本机偏好让整份 settings.json 读不出来

**症状**（用户原话）：桌面打开日程报
`设置保存失败：settings.json 结构无效，unknown variant `3days`, expected one of month week threeday day`，
以及 `日程创建失败：calendar.json 结构无效，missing field `startDate``；手工改 JSON 才恢复。

**查证结论**：不是正式版写坏的，是**开发中间版**留下的。证据三条：
① `git log --all -S "3days"` 全历史零命中——`3days` 从没进过任何提交；
② 日程代码是 `a075af7`（v0.9.0）一笔引入的，之前的版本根本没有 `calendar.json`；
③ 用户数据目录（`%LOCALAPPDATA%/kxtodo/todo-note-data`）里现存的 events 全带 `startDate`，
   且 `createdAt` 都落在 v0.9.0 开发那两天（10-25）。GUI 与 dev 构建**共用同一个数据目录**，
   所以中间版写的脏值被正式 release 原样读到了。

**但真正要修的不是那份文件，是这条脆弱性**：`calendar.view` 只是「上次停在哪一屏」的
本机 UI 状态，一个认不出的枚举值却能让**整份 settings.json** 反序列化失败——于是
「改任何设置」都报结构无效。数据字段严格是对的，本机 UI 偏好严格是错的。

修法（`model.rs`）：`lenient_view` + 三个 `deserialize_with`（diary/ledger/calendar 的 `view`），
认不出的值回落到该页默认视图。写路径**依旧严格**（`ops_config` 用 `parse` 校验，CLI 给错值直接拒）。
顺带把 `"3days"` 加进 `CalendarView::parse` 的别名表——既然认得出来，就按用户本意还原成三日视图。
`calendar.json` 的 `missing field startDate` 保持严格（那是数据，编不出来），用户已手工恢复。

钉子：`ops_config.rs` 新增 `view_enums_fall_back_instead_of_poisoning_settings`（含 `"3days"` 那一条）。

## 二、重复日程（`recurrence.rs` + `calendar.ts`，两份实现一张表）

### 2.1 语义（RFC 5545 的 RRULE 子集，只用本地墙上日期）

- `CalendarRepeat{freq, interval, byWeekday, byMonthDay, end, count, until}`。
  **不给「工作日」「每两周」各开一个枚举变体**——否则「每 3 周」就无处安放；
  它们是 `freq + interval + byWeekday` 的组合，预设只是糖。
- 周次锚在**开始日期所在周的周一**（ISO 周），与用户的「一周从周几开始」显示偏好无关——
  否则改个偏好重复日就漂了。
- 月/年遇到不存在的日号（2 月 30 日、平年 2 月 29 日）**跳过该次**，不折算到月末（RFC 口径）。
- `count` 数的是**规则生成的次数**（含首次）；`exceptDates`（「只删这一次」）同样占名额。
- 生成日期早于开始日期的（周频率选了开始日之前的星期）**不产出也不占名额**。

### 2.2 两份实现，一张用例表

`crates/core/src/recurrence.rs`（提醒计划 + CLI 展开）与 `src/lib/calendar.ts` 的
`occurrenceDates/expandForRange`（视图渲染）**必须逐条一致**。用例表在两处测试里一一对应
（`recurrence.rs` 的 `mod tests` ↔ `src/lib/__tests__/repeat.spec.ts`）：每天 / 每 3 天 /
工作日 / 每周只选周一 / 每两周 / 每月 31 日 / 每月默认日号 / 每年 2 月 29 / count / except /
until / 非重复。孪生常量 `REPEAT_COUNT_MAX = 999` 由 `frontend_contract.rs` 钉住。

### 2.3 展开的两个性能护栏

- **`skipAhead`**：不限次数的规则可以直接跳到区间附近（按月频率保守按 28 天/步估算再回退 2 步）；
  **按次数结束时必须从 k=0 数**（名额是全局的）。
- 保险丝数的是**迭代次数**（`MAX_STEPS = 4000`）而不是步号——`skipAhead` 之后步号可能已经
  远大于 4000，用步号当上界会让「每天重复了 20 年」的事件在查未来某个月时**一条都展不出来**。
- `list` 的展开只在**闭区间**做；只给 `--from` 时按一年为界（`OPEN_ENDED_HORIZON_DAYS = 366`），
  什么都不给就不展开（`occurrence = startDate`）。开区间展到永远等于骗人。

### 2.4 提醒（`reminders.rs::plan_calendar`）

重复事件按**视野内的每一次出现**各规划一条；收据键含 `at`，于是同一条规则在不同日期是
不同的键，各自只发一次。视野 = `CALENDAR_PLAN_HORIZON_DAYS(45) + 该事件最长的提前量`——
提前 30 天的提醒必须在 30 天前就进台账，否则到点时它从没「被见过在未来」，
按不补发纪律会被判跳过。非重复事件的行为一字未改（过去也照旧进台账，交给那层判跳过）。

### 2.5 拖动重复日程 = 改整个系列

「只改这一次的时间」需要例外实体（detached instance），本版**不做**，界面与文案都按
「改的是系列」说话。`calendar.ts::seriesChangesFromDrag`（有单测）：
- 平移量 = `occurrence → 新开始日期` 的天数差，整个系列一起挪，时长跟着新的起止走；
- **多星期的周规则（工作日、自定义周一三五）例外**：只改时刻与时长，不改哪几天
  （把整个系列挪到别的星期等于换了一条规则，用户拖的只是「这一次」）；
- 单星期周规则 / 按月某一天：日期平移**且** `byWeekday` / `byMonthDay` 跟着换
  （拖到周二就是以后都在周二）；
- 「每周」预设**刻意不写死星期**（`byWeekday` 留空 = 跟开始日期的星期走，core 的 preset 同口径），
  于是拖动改开始日期时星期自己跟着变，不需要再改规则。

### 2.6 删除的三档（业界口径）

`calendar.remove` 加 `occurrence`（只删这一次 → 写 `exceptDates`）与
`fromOccurrence`（此次及以后 → `repeat.until = 它前一天`；收到开始日之前就等于删整条）。
两个 scope 互斥在 **clap 层**先拦（`conflicts_with`），core 里的 `CALENDAR_OCCURRENCE_CONFLICT`
是给 GUI/agent 的兜底——集成测试因此断言「退出码非 0 且数据没动」，而不是断言 core 的错误码。

## 三、日程分类（自定义颜色）

- 数据：`CalendarCategory{id,name,color,isDefault,order,created_at,updated_at}`，
  与事件同住 `calendar.json`、同一个同步范围勾选，但同步上是**独立实体**
  （kind = `calendarCategory`）——照抄记账四种实体的做法：`is_calendar_kind()` +
  `calendar_entity_stamp(file, kind, id)` + `extract_entities` 多一段 + `apply_calendar_record`
  按 kind 分派 + engine 五处（拉取分桶 / 合并事务 / 对账水位 / 推送抑制 / resolve_conflict）。
  **`calendar_entity_stamp` 因此从 2 参变 3 参**，漏改的症状是分类永远对不上账、反复推。
- 配色（`calendar.ts::eventColors` → `{main, soft, line, onMain}`）：
  **左轨主色 + 块内淡色**，淡色一律 `mixWithWhite(main, 0.14)`、边框 `0.45`。
  用户自定义的颜色再深也不会把黑字压掉——文字色恒为深色，**不做对比度数学**。
  全天芯片与月视图「全天」芯片是实心底，字色按 `readableOn()`（WCAG 亮度）自动白/深。
  颜色工具住在新的 `src/lib/colors.ts`：**不 import 任何项目内文件**，否则
  `calendar.ts → styles.ts → defaults.ts → calendar.ts` 成环（`defaults.ts` 要 import
  `REPEAT_COUNT_MAX`）。
- 删分类**不删日程**：用它的日程退回「无分类」（core 与前端同时清引用）。与记账
  「名下有账的账户不让删」不同——分类只是外观归属，不该拦着用户整理。
- 「默认分类」全局互斥（`isDefault`），由**界面预选**（用户看得见），core 不在写入时偷偷塞——
  否则 CLI 建的日程会带上用户从没选过的分类。

## 四、编辑器重做成设置式表单（需求 4）

用户原话：「我要的不是一个编辑器界面，而是一个正经的日程配置界面……编辑器应该是嵌在
创建日程的界面的一个区块而已。」

- 骨架从「标题 + 一行元数据 + CM 铺满」改成**表单**：标题 + 一列 `.cal-field`
  （`grid-template-columns: 5.5em minmax(0,1fr)`，标签定宽所以每行对仗）+ 最后的
  `.calendar-details` 区块。行依次是：关联条目（有才显示）/ 全天 / 开始 / 结束 / 时长 /
  重复 / 提醒 / 地点 / 分类。
- **行里的浮层一律交给 `ContextMenu` 宿主**（日期、重复、提醒、分类）。它自带壳内定位、
  四边钳制、Esc / 点外关闭、输入法不抢焦点、移动端钻入——v0.9.0 那套「浮层塞在
  `overflow:hidden` 的对话框里被裁掉」（需求 5 的「提醒弹窗有可能弹出界面外」）一并没了。
  **不要再往对话框里塞绝对定位浮层。**
- **移动端不自动进编辑态**：`detailsActive = !isMobile`，进去只渲染详情的只读渲染
  （空则一行「点击添加详细信息」），点一下才 `ensureEditor()` 挂 CodeMirror 并聚焦；
  标题框也不自动聚焦（`if (!editingId && !get(isMobile))`）。桌面照旧：新建聚焦标题、
  编辑聚焦详情。
- 保留 v0.9.0 的写路径纪律：新建**保存才落盘**、标题与详情全空的隐式关闭视为放弃、
  关联条目详情双向同步、`onDestroy` 尽力保存一次。

### 4.1 DatePicker 的「确认」（需求 5）

`confirmMode` + `allowClear` 两个 prop：**时刻面板一律给「确认」不给「今天」**
（拨完滚轮再点「今天」会把刚选的日子改掉），日程编辑器连日期面板也给「确认」
（那里选的是具体某天的某个时刻，「今天」是误导）、且不给「清除」（开始日期没有清除语义）。
日记 / 记账 / 任务的日期浮层行为一字未改。

## 五、时间网格（需求 6 / 7 / 14 / 15）

### 5.1 「拖完才显示」的真根因（第三次踩同一个坑）

`$: renderedColumns = columns.map((c) => ({ blocks: displayBlocks(c) }))`——
**Svelte 只扫语句里字面出现的变量**，`blockDrag` 藏在 `displayBlocks` 的函数体里，
于是它不是这条 `$:` 的依赖，拖动预览只在别的东西让 `columns` 重算时才「顺带」出现。
v0.9.0 的注释还写着「必须用 `$:` 而不是 `{@const}`」——`$:` 同样中招，**函数间接层才是问题**。

修法：把依赖当**实参**传进去（`displayBlocks(column, blockDrag)`、
`blockVars(block.event, categories, accent)`、`isPast(block.event, today, nowMinutes)`），
让它们在语句里字面出现。模板里也一律吃 `$:` 算好的字段（`block.ghost` / `block.past` /
`block.vars` / `block.timeText`），不再调函数。
**这是本项目第三次踩「函数调用把依赖藏进闭包」**（v0.8.4 的影子状态、v0.9.0 的月格 `{@const}`）。

### 5.2 移动端「点一下落占位块」（需求 6）

触屏单击空白 = 在该处落一个 **15 分钟吸附、30 分钟长**的 `.cal-draft` 占位块；
拖它的上下边界（`touch-action: none` 的手柄）实时改起止；点块本身才进编辑器。
桌面保持 v0.9.0 的两条（拖选建块 / 单击建默认一小时）。

**占位块必须 `event.stopPropagation()`**：`.app-shell` 上有 `on:click={closeOverlays}`，
它会调本页 `closeOverlays()` → `grid.clearDraft()`——不吞掉冒泡的话，**落占位块的这一下
自己就把刚落的块收掉了**。探针实测：`draft` 赋值后紧接着一轮 `draft = null`。
（同族坑：`ColorPickerPanel` 挂在 App 层必须自己 stopPropagation，v0.8.6。）

### 5.3 一屏 12 小时 + 缩放（需求 15）

`hourHeight = 可视高 / 12 × zoom`（`ResizeObserver` 量 `.cal-scroll` 的 `clientHeight`，
布局像素，不受壳缩放影响）。桌面 Ctrl+滚轮、移动端双指捏合改 `zoom`，
落在 `settings.calendar.hourZoom`（0.5–3，**本机偏好不进同步共享子集**，与 `view` 同待遇）。
- 手势期间只改本地 `zoomPreview`，**松手/停顿才 `setConfig`**（滚轮防抖 240ms）——
  一路写设置会把 IPC 打满。
- 捏合必须用 `touchstart/touchmove` 且 `|nonpassive` + 两指时 `preventDefault()`：
  交给浏览器就变成整页捏合缩放，还会 `pointercancel` 把手势断掉。
- 三处注册点（`KNOWN_FIELDS` / `get` / `set`）之外还有**第四处 `set_default`**：
  漏掉的症状很隐蔽——平时读写都正常，只有「恢复默认设置」整轮失败在 `UNKNOWN_CONFIG_KEY`。
  现在 `every_known_field_is_resettable` 把这条钉死了（遍历 `KNOWN_FIELDS` 逐个 reset）。

### 5.4 文字换行（需求 7）与滚动条（需求 14）

块内标题 `white-space: normal` + `overflow-wrap: anywhere`，容器 `overflow: hidden`——
「绝不超出块范围」是底线，多出来的行被裁掉就是用户要的「被挡住」的观感。
`.short` 判据从「≤45 分钟」改成**实测高度 < 34px**（格高现在随缩放变，分钟数不再是好代理）。
`.cal-scroll` 与两个 sheet body 一律 `scrollbar-width: none` + `::-webkit-scrollbar{display:none}`。

### 5.5 今天的高亮圆（需求 8）

`align-items: baseline` → `center`，圆底尺寸从写死 24px 改成 `calc(var(--font-control) + 10px)`
并 `flex: 0 0 auto`——窄屏日期头是**列**布局，圆被 flex 压扁就成了椭圆切字。

## 六、全局悬浮提示（需求 13）

原生 `title` 太原始，但把几百处 `title=` 改成组件是巨大改动面。
`src/lib/tooltip.ts` 走**接管原生 title**：一份 window 级 `pointerover` 委托，
命中带 title 的元素就延迟 380ms 画自己的浮层，**到那一刻才摘掉 title**（存进 `data-tip`，
`pointerout` 原样还回去）。定位复用 `placePopover` + `popoverFrame`（元素下方居中、放不下翻上、
四边钳进壳内），样式在 `shared.css` 的 `.kx-tooltip`。

两条不能省的护栏：
1. **触屏不接管**（`pointerType !== "mouse"` 直接 return）——点一下弹个提示只会挡住内容。
2. **「刚点完、指针没动」不弹**（`armed` 标志：`pointerdown` 卸保险，`pointermove` 超过 4px 上保险）。
   两个理由：刚点过的控件不需要再解释一遍；更重要的是——点完之后界面常在**原地换成另一个控件**
   （搜索按钮变「关闭搜索」），指针没动就会触发一次 pointerover，这时摘掉 title 会让任何按
   `[title=…]` 找元素的代码（本仓库 170+ 处测试选择器）在那一瞬间找不到目标（v084 实测挂掉）。

  `task-calendar-icon` 的四个 grid 变体**——图标挤进正文那一列、正文被顶到下一行，
  看上去就成了「图标在右边、文字右对齐」。补 `.app-shell.mobile` 的四条
  （compact / plain.compact / +pinned 两两组合）；`grid-column` 由桌面那几条给（列号一致，
  移动端只是砍掉尾部 edit-button 那一列）。
- **工具栏**（需求 10）：去掉「今天」，只留「日期 ‹ ›」+「现在」；「现在」= 跳回今天**并**滚到此刻
  （月视图就是回到本月）。`.calendar-today-btn` 的 CSS 一并删干净。
- **FAB**（需求 9）：移动端 `bottom` 从 24px 改成 `calc(97px + safe-area)`，与日记/记账同高。
- **剪切板**（需求 16）：桌面路径框 `rows="1"` + JS 自动增高（不用 `field-sizing`——WebKitGTK 不认；
  不用 `<input>`——它压根不折行），移动端保持 2 行基线并可继续长高；**「选择路径」整个功能删掉**
  （Kotlin `listSaveDirs` / 桥 / 类型 / 菜单 / CSS 一个不留）；安卓「打开文件夹」重写——
  v0.9.0 有两处「打开的不是配置的目录」（路径含 Pictures 就特判成 MediaStore 的**全局相册集合**；
  其余把 FileProvider 目录 URI 丢给 `ACTION_VIEW`，DocumentsUI 不认），现在按
  `DocumentsContract.buildDocumentUriUsingTree` 构造真正的文档 URI，接不了就**如实报错**，
  绝不打开别的地方充数。
- **图片链路**（需求 16 后半，「总是有收不到图」）：查出的单点最大缺陷是
  **安卓收到的图片从来没写进过系统剪切板**——core 把图片落在内部数据目录
  `runtime/clipboard-inbox`，`ApkBridge.fileUri` 的白名单只有 cache/external-files，
  返回 null → 整项跳过 → `writeClipboard` 还返回 `""`（成功）→ 没有任何提示。
  现在过不了白名单的先拷进 `cacheDir/clipboard-out/`（`file_paths.xml` 里有 `cache-path`）再发 URI，
  且**有内容没写进去就返回错误串**让前端弹 Toast。另外七处：前端签名把 `imagePath` 当占位符
  （连抄两张不同的图，第二张起被当重复吞掉）、图文混合复制时 html 折文件把图挤掉
  （桌面 `write()` 改成一次会话写全 CF_DIBV5 + CF_UNICODETEXT + CF_HDROP）、
  arboard 3.7 只读 PNG/CF_DIBV5（补 CF_DIB 裸解码 `rgba_from_cf_dib`）、
  DIBV5 全零 alpha → 全透明「看不见的图」（`repair_zero_alpha`）、
  服务启动后第一次复制被当基线吞掉（空读也要 prime；安卓的 `primed` 曾是死代码）、
  自己写回的内容被回读成「新复制」再回声发回去（记 `GetClipboardSequenceNumber`；
  安卓 PNG 改成拷字节不解码重编，签名才稳定）、以及一切静默丢弃都补上事件文案
  （「图片超上限未发送」等）。
